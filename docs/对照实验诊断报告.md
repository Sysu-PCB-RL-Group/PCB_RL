## 一、实验 A：专家注入有效性 —— ✅ 基本有效

对比 `with_expert`（专家预训练+注入）与 `baseline`（无专家），看 **best reward**：

| 板子 | with_expert Best | baseline Best | 判断 |
|------|------|------|------|
| Connector | **168.2** | 128.1 | ✅ 专家显著提升 |
| 灯板2 | **282.3** | 194.9 | ✅ 专家显著提升 |
| 开关小板 | 150.0 | 150.8 | ➖ 无差异 |
| 按键侧板 | 109.8 | 109.8 | ➖ 无差异 |
| Button | -153.6 | -156.9 | ➖ 均失败 |

**初步结论**：专家注入对 **Connector、灯板2** 有明显正向作用（best 提升 31%~45%）；对开关小板、按键侧板无影响（本来单板就能学好）；对 Button 两者都失败，专家无法挽救。

**注意**：best 是"单次最高"，易受噪声影响。需要看曲线趋势（后20%均值）才更稳，见下文"共性问题"。

## 二、实验 D：reward 尺度错配假说 —— ❌ 完全失效

**现象**：`expert_nopen`（专家 reward 无惩罚）与 `expert_pen`（专家 reward 带惩罚）的所有板数据**逐项完全相同**：

```
Connector: 168.3/-150.1  == 168.3/-150.1
开关小板:  150.3/68.8    == 150.3/68.8
Button:   -153.9/-161.3  == -153.9/-161.3
```

连专家轨迹的 reward 都逐条相同（如 Connector 首条 reward 4.163... 完全一致）。

**根因（脚本 bug）**：
`Config` 类中**未定义 `EXPERT_APPLY_PENALTIES` 属性**。`run.py` 里 `Config.load_from_file()` 加载临时 config 时，`if hasattr(cls, key)` 判断失败 → `setattr` 不执行 → `Config.EXPERT_APPLY_PENALTIES` 恒为默认 `False`。

因此无论 `config_pen.txt` 写的是 `=1` 还是 `=0`，实际训练都用**无惩罚**专家轨迹，两组无差别。

**结论**：实验 D 的 reward 错配假说**未能得到任何验证**，数据无效。需修复后重跑。

**修复方案**：在 `Config` 类补上 `EXPERT_APPLY_PENALTIES: bool = False` 定义，确保 `load_from_file` 能注入。

## 三、实验 E：跨板 vs 单板 —— ⚠️ 对比无效

**现象**：cross（跨板训练）reward 整体低于 solo，且：

1. **训练量不对等**：cross 每板只有 **~2000 episode**（10000 轮 ÷ 5 板，每板随机被选中约 1/5），而 solo 有完整 **10000 episode**。**cross 训练量只有 solo 的 1/5**，比较不公平。

2. **reward 函数不一致（致命）**：
   - cross 的 reward 被截断在 `[0, 100]`，min 可为 0
   - solo 的 reward 可达 150~282，min 为负（有惩罚）
   - 说明 cross（跨板训练 `board=None`）和 solo（单板训练）用了**不同的 reward 计算路径**，两者不在同一尺度上比较，**结论无效**。

| 板子 | cross Best/末20 | solo Best/末20 | 备注 |
|------|------|------|------|
| Connector | -2.5/-164.4 | 168.2/-144.4 | reward 尺度不同 |
| 开关小板 | 100.0/55.7 | 150.0/73.4 | cross 被 clip 到 100 |
| 按键侧板 | 100.0/96.0 | 109.8/107.7 | cross min=0 无惩罚 |
| 灯板2 | 100.0/-22.5 | 282.3/-30.2 | reward 尺度不同 |
| Button | -159.1/-167.3 | -153.6/-160.7 | 均失败 |

**结论**：跨板训练是否优于单板**无法判断**。需统一 reward 函数 + 训练量后再比。

## 四、共性问题：训练普遍"后段不稳"

观察所有组曲线的 **10 段均值**，发现一个系统性现象：

- **Connector**：with_expert 从 -160 爬到 -132 后又回落 -149；baseline 恒在 -161 几乎不动（完全没学习）
- **Button**：两组成绩恒定在 -160~-170（彻底失败）
- **开关小板/灯板2/按键侧板**：能学到正值，但后 20% 均值多数低于 best，说明有回落

**解读**：
1. **Button、Connector 板"学不动"**：reward 长期为负。这两个板可能问题出在**元件布局本身难以满足间距约束**，或网格分辨率下探索空间太大。
2. **reward 后期不稳定**：best 高但后段回落，符合 **DQN 探索/利用平衡不稳定**，或 reward clip 边界（-30~+60/步）下的目标振荡。
3. **reward 尺度错配真实存在**：正是实验 D 想验证的问题——专家 reward 无惩罚（可到 100+）与 RL 环境带惩罚（clip 到 -30~60）尺度不同，可能导致学习不稳。

## 五、总体判断与建议

**这次对照实验的价值**：实验 A 提供了**有效**的"专家注入有效性"证据；同时暴露了实验 D 的脚本 bug 和实验 E 的设计缺陷。

**建议下一步**（按优先级）：

1. **修复实验 D**：在 `Config` 类补 `EXPERT_APPLY_PENALTIES`，重跑实验 D——这是验证"reward 错配假说"（最可能解释训练不稳定的根因）的关键。
2. **重设计实验 E**：让跨板训练和单板训练使用**相同的 reward 函数 + 相同的训练量**（例如跨板训练也跑足 5×10000 轮，再按板提取），才能公平对比迁移能力。
3. **排查 Button/Connector 学不动**：这两个板 reward 长期为负，需检查是奖励设计、网格分辨率、还是板子本身布局复杂度问题。

## 八、Button/Connector 学不动的根因排查（2026-08-21）

### 关键结论：不是元件数量最多，而是**元件密度过高**

实测各板元件面积占比（总面积/板框面积）：

| 板子 | 板框mm² | 元件mm² | **密度%** | 可移动数 | 学得动？ |
|---|---|---|---|---|---|
| **Button** | 216.0 | 146.7 | **67.9%** | 2 | ❌ 学不动 |
| **Connector** | 224.3 | 101.4 | **45.2%** | 8 | ❌ 学不动 |
| 灯板2 | 179.0 | 43.5 | 24.3% | 6 | ✅ |
| 开关小板 | 84.6 | 13.9 | 16.5% | 6 | ✅ |
| 按键侧板 | 75.4 | 4.6 | 6.2% | 2 | ✅ |

**规律完全一致：学不动的两块板恰是密度最高的两块（67.9%、45.2%），学得动的板密度都 ≤24.3%。**

### 具体机制

- **Button（密度 67.9%，最严重）**：板框仅 18×12mm=216mm²，可动元件 U1 按键（6.63×11.35≈75mm²）+ CN3 通孔连接器（6.5×6.07≈39mm²）占 114mm²，加上 2 个固定 Pad。两个大元件几乎挤满板框，**几乎不存在不重叠的合法摆放** → 重叠惩罚必然持续 → reward 长期为负。
- **Connector（密度 45.2%）**：8 个全可动元件（6×4×2mm Pad + 2×4×4mm UFL 天线座）挤在 14.2×15.7mm=224mm² 板框内，动作空间组合约 155 万（最大），**合法解少 + 搜索空间大** → 极难找到好解。

### 为什么其他板能学动
灯板2（24.3%）、开关小板（16.5%）、按键侧板（6.2%）元件稀疏，有大量合法布局空间，RL 能轻松找到不重叠且品质好的布局。

### 可选缓解方向（未实施，需评估）
1. **放宽重叠/板框惩罚**：对高密度板降低重叠惩罚系数，或允许部分重叠。
2. **扩大布局区域**：把 valid_area 外扩（如增加 BOARD_MARGIN）给元件更多空间。
3. **分阶段放置**：先约束不重叠，再优化品质。
4. **直接以密度作为板子可训练性的筛选指标**：密度 >~40% 的板子天然难学，可跳过或降级为参考。

> **第八节"密度筛选"方向经复核已放弃**：专家板子一定有解（专家手工完美布局），
> 全部板都该训练，不该筛选。真正原因是环境的 valid_area 定义与专家贴边布局不兼容，见第九节。

## 九、Button 学不动根因修正：valid_area 内缩导致无解（2026-08-21 已修复）

### 推翻第八节结论：不是"密度高"，是"valid_area 内缩"

用户提出关键质疑：**专家板子一定有解（专家手工完美布局），不该筛选**。复核后确认正确。

Button 板原始文件里，U1 按键 bbox=(148.24,96.36)~(154.87,107.70)，**专家是贴边放的**（Y 贴板框 96.03~108.03）。但环境：

```python
valid_area = (min_x+MARGIN, min_y+MARGIN, max_x-MARGIN, max_y-MARGIN)  # MARGIN=1.0 内缩
# Button: valid_area 高 = (108.03-1.0)-(96.03+1.0) = 10mm
expected_h = int(footprint_h / CELL_SIZE) = int(11.35/1.0) = 11 格
# grid_height = int(10/1.0) = 10 < 11 → U1 放不下 → mask 全屏蔽 → 学不动
```

**根因**：valid_area 内缩 1mm + 网格取整，导致 U1 需要 11 格而区域只有 10 格 → 物理上无合法解 → reward 恒负。这不是板子没解，是**环境把专家能贴边放下的元件逼到无解**。

### 实测验证（各板 MARGIN 下的可放置性）

| 板子 | 最大元件需格(h) | 板框h | MARGIN=1.0(旧) | MARGIN=0.0(新) |
|---|---|---|---|---|
| **Button** | 11 | 12.0 | **NO** ❌ | **OK** ✅ |
| Connector | 4 | 15.7 | OK | OK |
| 灯板2 | 4 | 12.2 | OK | OK |
| 按键侧板 | 1 | 18.0 | OK | OK |
| 开关小板 | 1 | 9.2 | OK | OK |

仅 Button 在旧配置下放不下，MARGIN=0 即解决，且不影响其他板。

### 修复内容

1. `env/pcb_layout_env.py`：`Config.BOARD_MARGIN: 1.0 → 0.0`（valid_area 不再内缩，等于板框）
2. `config/argument.txt`：`BOARD_MARGIN = 0.0`

### 修复后冒烟测试

Button grid 10×10 → 18×12，需格 6×11 ≤ grid → **U1 能放下**；全部板 grid ≤100 安全。

### ⚠️ 必须重生成专家轨迹
expert_trajectory.py 以 `env.valid_area` 为坐标基准，改 valid_area 后旧专家轨迹网格索引失效，**必须重新生成**（`_regen_all_expert.py`）。

### Connector 学不动原因：同层 + 间距阈值过严（独立问题，待决策）

Connector 尺寸能放下（需 4 格，MARGIN 全 OK），学不动另有原因。实测 8 个可动元件：

| 元件 | 封装 | 层 | pkg_type | nets |
|---|---|---|---|---|
| 6×Pad_e* | 4×2mm | **0(TOP)** | **4** | 4个GND + X/Y_AXIS |
| JP1/JP2 | 4×4.7mm UFL | 0(TOP) | 4 | GND + X/Y_AXIS |

**全部同层（TOP）+ 全部 pkg_type=4**。而 `spacing_threshold_for` 对 pkg_type=4 取阈值 **2.0mm**。8 个元件同层且互相间距 ≥2.0mm：每个元件占 (4+2)×(2+2)≈24mm²，8 个 ≈192mm²，而 valid_area 仅 14×15=210mm²，**填充率约 91%** → 几乎无合法排布 → 学不动。

**这是独立于 Button 的问题**（Button 是尺寸放不下，Connector 是间距阈值+同层太挤）。需单独决策：
- 是否调低 pkg_type=4 的间距阈值
- 是否允许元件分布在两层
- 是否接受 Connector 作为"难以训练的特例"降级处理

当前修复（BOARD_MARGIN=0）已解决 Button，Connector 留待单独处理。
