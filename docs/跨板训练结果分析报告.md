## 三、关键发现与分析

### 3.1 表现分级

- **优秀**：按键侧板（2 元件）
  - 初始即接近满分，全程稳定
  - 2 个元件都能放置，reward 始终在 90~110
  - 说明小板上专家轨迹质量高，BC 预训练有效

- **良好但波动大**：灯板2、开关小板（6 元件）
  - 开关小板：从 R≈60 逐步上升到 R≈100+，学习趋势明显
  - 灯板2：有极高峰值（R=169），但波动极大，大量负 reward episode
  - 6 元件板复杂度适中，模型能学到但不够稳定

- **失败**：Connector（8 元件）、Button（2 元件）
  - Connector：始终卡在 -150 ~ -200，无任何改善迹象
  - Button：始终卡在 -160，placed 仅 0.8~1.0（2 个元件都放不进去）
  - **Button 尤其异常**：2 元件小板理论上最简单，却完全失败

### 3.2 从图表观察到的动态（见 `cross_reward_compare.png`）

1. **按键侧板**：从 ep 0 就稳定在 100 左右，几乎无波动，说明专家轨迹直接给出了优质策略
2. **开关小板**：平滑曲线从 ~60 逐步爬升到 ~100，学习过程清晰可见
3. **灯板2**：平滑曲线在 0 附近波动，但散点有大量 100+ 的峰值，说明模型偶尔能找到好解但不稳定
4. **Connector**：全部点在 -150 ~ -200 区间，平滑曲线几乎水平，完全没有学习
5. **Button**：全部点在 -160 附近，比 Connector 还集中，placed 始终 < 1，说明元件根本放不进去

### 3.3 问题诊断

#### Button 板（最严重）
- **现象**：2 个可移动元件，placed 始终 0.8~1.0，reward 始终 ≈ -160
- **可能原因**：
  1. 该板的 2 个元件都是固定元件（不可移动），但环境误判为可移动
  2. 元件 footprint 或约束导致无法合法放置（如尺寸过大超出板框）
  3. 专家轨迹生成时对该板处理异常（如 apply_penalties=False 但专家本身就有问题）
  4. 该板的 kicad_pcb 文件中元件被锁定（locked）或层设置异常
- **建议**：单独检查 `data/kicad-native-batch/htx-studio-project_kpilekig-42ad306f--Button-cbd1bfb1.kicad_pcb` 的元件属性

#### Connector 板（8 元件）
- **现象**：reward 始终负，placed 从 5.2 提升到 6.1（有轻微改善）但 reward 无改善
- **可能原因**：
  1. 8 元件板复杂度最高，模型容量不足（当前 MAX_MOVABLE 可能不够）
  2. 约束过于严格（如 net length 惩罚过重）
  3. 专家轨迹对该板覆盖不足（800 条可能不够 8 元件的复杂度）
  4. Reward 设计问题：placed 提升但 reward 不升，说明惩罚项权重可能过高

## 四、专家轨迹应用机制详解

### 4.1 是否使用了专家轨迹？

**是的，完全启用了专家轨迹注入。**

日志确认：
```
Loaded 2400 expert transitions
Phase 1: BC Pretraining — 50 epochs on expert transitions
Phase 2: loaded BC pretrained weights from ./result/cross_50000/bc_pretrained.pt
```

### 4.2 专家轨迹如何生成？

每板独立生成，参数来自 `config/argument.txt`：

| 参数 | 值 | 含义 |
|---|---|---|
| `EXPERT_TRAJECTORIES_PER_BOARD` | 20 | 每板生成 20 条专家轨迹 |
| `EXPERT_EPSILON_DECOMPOSE` | 0.5 | 动作分解概率（50% 用分解动作） |
| `EXPERT_POS_NOISE_PROB` | 0.2 | 位置噪声概率 |
| `EXPERT_ROT_NOISE_PROB` | 0.1 | 旋转噪声概率 |

生成流程（`env/expert_trajectory.py`）：
1. 读取 KiCad 原始布局（元件的初始位置作为专家位置）
2. 对每元件，按顺序执行放置动作（位置 + 旋转）
3. 应用噪声和动作分解增加多样性
4. **关键：使用 `apply_penalties=False`**（用户版本）
   - 专家 reward 只计算正向奖励（net length、alignment 等）
   - 不扣除约束违反惩罚
   - 因此专家 reward 全为正数（验证：5 个 JSON 的 reward 均为正）

### 4.3 专家轨迹如何应用到跨板训练？

**两阶段注入机制**：

#### Phase 1：BC 预训练（Behavior Cloning）
- **输入**：全部 5 板的 2400 条专家 transition（混合在一起）
- **方式**：监督学习，用专家 (state, action) 对训练 DQN 的策略网络
- **目的**：让模型先学会"合理放置"的基本策略，避免冷启动
- **输出**：`bc_pretrained.pt`（50 epoch 后的 checkpoint）

#### Phase 2：RL 训练 + 专家经验回放
- **初始化**：加载 Phase 1 的 BC 权重作为起点
- **Buffer 结构**：`ExpertReplayBuffer`
  - 专家区：2400 条（常驻，不可覆盖）
  - 普通区：9600 条（环形覆盖，5× 专家数）
  - 专家比例：每次采样 batch 的 **20% 来自专家区**
- **采样方式**：
  - 专家区：均匀随机采样（无 PER 优先级）
  - 普通区：PER 优先级采样（基于 TD-error）
- **跨板特点**：
  - 5 板的专家经验**混合存储**在同一个 buffer 中
  - 每轮训练随机抽一块板，该板的 RL 经验进入普通区
  - 采样时 20% 从全部 2400 条专家经验中随机抽取（可能抽到任意板的专家经验）
  - 这种"跨板共享专家经验"的设计，让小板的优质策略可能迁移到大板

### 4.4 跨板训练与专家轨迹的交互效果

| 方面 | 效果 |
|---|---|
| 正向迁移 | 按键侧板（2 元件）和开关小板（6 元件）的优质专家经验，可能帮助了灯板2 的学习 |
| 负向干扰 | Button 板的异常专家经验（如果本身有问题）可能污染了共享 buffer，影响其他板 |
| 专家比例 | 20% 专家 + 80% RL 经验，保证模型不会过拟合专家，仍能探索新策略 |
| BC 预训练 | 50 epoch 的监督学习让模型有了基本放置能力，RL 阶段从非随机起点开始 |

## 五、下一步建议

### 5.1 立即排查
1. **Button 板**：检查 `data/kicad-native-batch/...Button...kicad_pcb` 的元件是否被锁定、层设置是否正确
2. **Connector 板**：单独运行 1 万轮训练，观察是否仍是同样问题
3. **验证专家轨迹**：检查 Button 和 Connector 的专家 JSON 中 reward 是否为正、动作是否合理

### 5.2 优化方向
1. **增加专家轨迹数**：Connector（8 元件）可能需要 > 20 条专家轨迹
2. **调整专家比例**：当前 20%，可尝试 30% 或 10% 做对照
3. **分板专家 buffer**：当前 5 板专家混合，可尝试每板独立 buffer，只采样该板专家
4. **Reward 调参**：Connector 的 placed 提升但 reward 不升，需检查惩罚项权重
5. **模型容量**：8 元件板可能需要更大的网络或更长的训练

### 5.3 对照实验建议
- 关闭专家轨迹（`--use_expert False`），看纯 RL 在 5 万轮的表现
- 只用单板训练（如开关小板），与跨板结果对比，评估迁移效果
