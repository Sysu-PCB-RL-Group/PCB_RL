# 固定维度架构移植说明

> 日期：2026-08-02
> 操作：将 `PCB_RL(change)` 中的固定维度架构移植到 GitHub 最新版 `PCB_RL`

---

## 一、移植背景

- `PCB_RL(change)`：基于较早 commit 独立开发的固定维度版本，包含 Dict 观测 + Slot Encoder 架构
- `PCB_RL`（当前）：GitHub 最新版 `cb3e11f`，包含 Reward Shaping、Mask 精简、可视化、数据锁定等训练优化

两个仓库分别解决了不同问题——新版聚焦**训练效果**，旧版（你的改动）聚焦**架构泛化**。本次移植取两者之长合并到当前仓库。

---

## 二、移植策略

**原则**：以新版为主体，替换其观测/网络/维度层为固定维度架构，保留所有训练优化。

| 层面 | 保留新版 | 替换为你的改动 |
|---|---|---|
| Reward 权重 | ✅（惩罚 10x 缩小） | — |
| Reward Shaping | ✅（quality_scale 分级升温） | — |
| Mask 策略 | ✅（step 1-4 无 mask） | — |
| Epsilon 衰减 | ✅（指数衰减 + EPSILON_MIN） | — |
| Target 端掩码 | ✅（nsid=0 placed_flag 屏蔽） | ✅（改为 Dict 版提取方式） |
| 可视化 | ✅（Loss 曲线每 100 ep） | — |
| Checkpoint | ✅（仅存 best + 训练前备份） | — |
| 数据过滤 | ✅（movecall 排除） | — |
| Mock 模式 | ✅ | — |
| **观测空间** | — | ✅（Box → Dict） |
| **网络架构** | — | ✅（MLP → Slot Encoder） |
| **维度常量** | — | ✅（MAX_MOVABLE=384 等） |
| **Global features** | — | ✅（8 维全局特征） |
| **文件日志** | — | ✅（training_log.txt） |
| **训练汇总** | — | ✅（training_summary.json + 文字） |

## 三、逐文件改动详情

### 3.1 `env/pcb_layout_env.py`

| 位置 | 改动 | 说明 |
|---|---|---|
| Config 类 | 新增 `MAX_MOVABLE=384, GRID_W=512, GRID_H=512` | 固定维度天花板常量 |
| `observation_space` | `Box(变长)` → `Dict{slots:(384,8), global:(8,)}` | 结构化观测，支持跨 PCB |
| `_get_obs()` | 返回 `(MAX_MOVABLE, 8)` 矩阵 | slot 共享语义，padding 自动补 0 |
| `_compute_global_features()` | 新增方法 | 8 维：板框 + 放置比例 + pending 连续编码 |
| `_get_obs_with_pending()` | 返回 `dict` | 替代平铺向量拼接 |
| `_build_mask_for_step(0)` | 固定长度 `(MAX_MOVABLE,)` | 默认非法 + 显式放行，i >= N_movable 自动为 False |

**未改动**：`_calculate_reward()`（quality_scale 升温逻辑完全保留）、`_assemble_action()`、`env.step()`、`env.reset()`。

### 3.2 `dqn/network.py`

**完全重写**。旧架构 vs 新架构：

```
旧（新版 GitHub）:
  obs 平铺向量 → Linear(obs_dim, 512) → Linear(512, 256) → Linear(256, 128)
  → 5 个 Head [384, 512, 512, 4, 2]

新（移植后）:
  Dict obs:
    component_slots (B, 384, 8) → SlotEncoder(8, 16) 共享权重
      ├── Step 0: head_comp(16, 1) → per-slot Q (B, 384)
      └── Step 1-4: mean_pool → (B, 16)
                      concat(global_features (B, 8)) → (B, 24)
                      Linear(24, 256) → Linear(256, 128)
                      → 4 个 Head [512, 512, 4, 2]
```

| 指标 | 旧架构 | 新架构 |
|---|---|---|
| 参数量 | ~2.1M | **172K** |
| 输入层 | 变长，每个 PCB 不同 | 固定 384×8 + 8 |
| 元件对称性 | 无（位置编码） | 有（共享 slot encoder） |
| 全局信息 | 无 | 8 维 global_features |

### 3.3 `dqn/agent.py`

| 项目 | 旧 | 新 |
|---|---|---|
| 构造函数 | `DQNAgent(obs_dim, n_movable, grid_w, grid_h)` | `DQNAgent(n_movable, grid_w, grid_h)` — 去掉 obs_dim |
| `select_action` | 接受 `np.ndarray` obs | 接受 `dict` obs，支持 `mask=None`（新版特性） |
| `learn` | 平铺向量 `torch.FloatTensor(obs_batch)` | Dict 批量转换 + 子集索引；target 端 nsid=0 掩码改为从 `component_slots[:,:,0]` 提取 placed_flag |

### 3.4 `dqn/replay_buffer.py`

新增 `_batch_dict_obs()` 静态方法，`sample()` 返回 batched dict 而非平铺数组矩阵。

### 3.5 `run.py`

**保留全部新版功能**：Loss 曲线、best checkpoint、备份、指数 epsilon、curriculum、mock 模式、movecall 过滤。

**新增**：
- `_init_agent_and_buffer()` 改用 `Config.MAX_MOVABLE/GRID_W/GRID_H` 构造 Agent
- `run()` 中添加 `FileHandler` 写 `training_log.txt`
- `run()` 中记录每个 episode 的 reward/placed 列表
- `_write_pcb_summary()` / `_write_final_summary()` 方法

### 3.6 `env/mock_pcb.py`

`_init_env_from_kicad()` 中 `observation_space` 同步为 Dict 结构。

## 四、保留的新版核心功能（不改动）

### Reward Shaping：品质项分级升温

```python
# Config 常量
QUALITY_START_EP = 10000      # 前 10000 ep: quality_scale = 0（纯约束）
QUALITY_RAMP_EP  = 2000       # 10000-12000 ep: 线性升温到 1.0

# 品质项（net_aggregation, congestion, decoupling, large_comp）
# 乘以 quality_scale，先学"不碰撞不出界"，再学"布局好"
```

### Mask 精简

```python
# step 0: 有掩码（已放置/固定元件不可选）
# step 1-4: 无掩码（Agent 自学边界，通过 reward penalty 惩罚出界）
```

### Target 端掩码（nsid=0）

```python
# 计算 target Q 时，屏蔽已放置元件（从 component_slots[:,:,0] 提取 placed_flag）
# 避免 target Q 被已放置元件的高 Q 值虚高
placed_flags = sub_next["component_slots"][:, :, 0]  # Dict 版更简洁
comp_mask = (placed_flags < 0.5)
next_q_all[~comp_mask] = -float('inf')
```

### 其他保留

- 指数 Epsilon 衰减：`ε = EPSILON_MIN + (START - MIN) * exp(-4t/Emax)`
- Loss 曲线可视化：每 100 ep 生成 PNG + JSON
- Best checkpoint：仅保存 reward 最高的模型（`_best.pt`）
- 训练前自动备份旧结果到 `backup/时间戳/`
- Mock 模式：`--mock` 加载 JSON 数据
- movecall PCB 自动过滤

### 6.5 将 JSON 布局导出为 KiCad 可打开的文件

```powershell
D:\KiCad\bin\python.exe -c "
import json, os
os.environ['KICAD_PATH'] = r'D:\KiCad'
from env.pcb_layout_env import PCBLayoutEnv

# 1. 加载原始 PCB
env = PCBLayoutEnv(r'data\kicad-native-batch\ran-pang-airlink-86231b34--开关小板-883285b3\ran-pang-airlink-86231b34--开关小板-883285b3.kicad_pcb')

# 2. 加载最佳布局 JSON
with open('result/best_layout/ran-pang-airlink-86231b34--开关小板-883285b3_best.json', 'r', encoding='utf-8') as f:
    best = json.load(f)

# 3. 把 JSON 坐标写入 components
for comp_data in best['components']:
    ref = comp_data['id']
    if ref in env.kicad.components:
        c = env.kicad.components[ref]
        c.bbox = tuple(comp_data['bbox'])
        c.rotation = comp_data['rotation']
        c.layer = comp_data['layer']
        c.is_placed = comp_data['is_placed']
        c.is_fixed = False

# 4. 导出 .kicad_pcb
output_path = 'result/best_layout/ran-pang-airlink-86231b34--开关小板-883285b3_best.kicad_pcb'
env.kicad.export_layout(output_path, env.kicad.components)
print('Done: ' + output_path)
env.close()
"
```

导出后在文件资源管理器中双击 `.kicad_pcb` 文件即可用 KiCad 打开查看。
