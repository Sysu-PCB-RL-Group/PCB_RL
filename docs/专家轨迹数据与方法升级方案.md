## 0. 为什么用 DT测试 的方法（一句话版）

**因为 DQN 侧需要的东西（多样的、含意图的、真实的布局数据源 + 数据质量门禁），
DT测试 已经建成并验证过了**——不是"借鉴思路"，而是直接复用已跑通的代码和数据：

| DQN 专家管线的缺口 | DT测试 已有的现成资产 | 成熟度 |
|---|---|---|
| 数据同构（1 块板自增广，93% 布局是同一解族的平移） | **V5 真实子电路 691 板**（开源 KiCad 人类布局裁剪，`data/boards_json_subcircuit_train/`） | ✅ 已落盘 |

| 缺数据质量门禁 | `measure_expert_quality.py`（SA vs 随机 61/61、vs 启发式 58/61 的验收体系）+ `tests/test_structural.py` | ✅ 已实现 |
| **旋转几何 bug（本次新发现，见 §1）** | **M0 已修过同类 bug**：`env/pcb_utils.py:94 rotate_pins`，含完整注释与验证 | ✅ 现成可移植 |

## 1. 前置必修：旋转几何 bug（阻塞项）

### 1.1 问题描述

DQN 全管线中**旋转只改标签、不改几何**：

- `env/pcb_layout_env.py::_assemble_action`：`gx2 = gx1 + footprint_w/CELL`，
  `gy2 = gy1 + footprint_h/CELL`——**不看 `_pending_rot`**，90°/270° 时宽高应互换；
- `env/expert_trajectory.py::_compute_expert_reward` 与 `_build_step_transitions`：
  重建 bbox 同样用未旋转的 `footprint_w/h`；
- 全管线 grep 无 `rotate_pins`：**引脚相对偏移从不随旋转换算**
  （引脚错 → 去耦距离 / net 聚合 / 拥塞全部算错）；
- 变异路径 `_mutate_component_state` 改旋转后 bbox 完全不动。

### 1.2 为什么现在才发现

当前训练板（开关小板）6 个元件**全是 1.524×1.524 正方形对称焊盘**：
宽高互换是恒等变换、引脚在中心旋转不变 → bug 无害化。
所有历史验证（reward +157、负样本 0%）在此板上依然成立。
**但它是定时炸弹**：数据升级的目标（长条元件、真实板）恰恰是让 bug 显形的环境。
DT 侧 M0 已实测过同类 bug 的威力——33.5% 组件非零旋转时，55% 动作的 HPWL 是拿错引脚算的。

### 1.3 修法（移植 DT 的 `rotate_pins` + 宽高互换）

1. 移植 `DT测试/env/pcb_utils.py:94` 的 `rotate_pins(pins, w, h, rot)` 到
   `env/pcb_utils.py`（含 `(w,h)` 坐标系说明与逆变换）；
2. `_assemble_action`：按 `_pending_rot` 交换 expected_w/h（rot∈{1,3} 时互换）；
3. `_compute_expert_reward` / `_build_step_transitions`：重建 bbox 时按目标旋转
   互换 footprint_w/h，并对 pins 调 `rotate_pins`；
4. `_mutate_component_state`：旋转变异后同步互换 bbox 宽高（保持中心不变）；
5. `env.step()` 落子处同样按 rot 互换；
6. 单测：构造 2×1 长条元件，rot=1 后断言 bbox 宽高互换、引脚位置随转
   （`tests/test_pcb_utils.py` 加 2 用例，参照 DT `tests/test_structural.py` 写法）。

**代价**：修复后旋转语义变化 → 旧 checkpoint 与旧专家数据作废，需重生成。
当前板是正方形元件，重生成数值几乎不变（可用此板做回归对照：新旧管线数据指标应一致）。

## 2. 数据现状（2026-08-30 深析结论）

20010 条 / 667 轨迹 / 4002 次放置：

| 维度 | 数字 | 含义 |
|---|---|---|
| 健康性 | 负样本 0%（min +1.908），坐标无聚集，可复现 | ✅ 干净 |
| 不同最终布局 | 618/667（93%） | **假多样**：top 布局互为整体平移/±1 格版本，同一解族 |
| 不同放置顺序 | 202/720（28%），主序 13.6% | 顺序多样性尚可 |
| 每元件落点 | ~113-120/1296 格（9%） | 集中在原始簇附近 |
| 旋转分布 | 每元件 ~90% 黏主旋转，其余各 2-4%；熵 68% | **旋转头欠训练** |
| 放置级 reward | 先放 108 → 后放 146，p5=101.5 | 品质项冷启动，顺序偏置被放大 |

一句话：**一块板、一个解族、深挖两万条。干净，但同质。**

## 4. P1 数据源三层扩容（详细）

**数据来源真实性分级**（按"离真实人类设计有多远"排序，可按需取舍）：

| 层 | 来源 | 布局来源 | 结构（网表/电源网/固定件）来源 | 分类 |
|---|---|---|---|---|
| L1 | 5 块真实 KiCad 板 | 人类布局（反向拆解+微变异） | 真实 | **全真实** |
| L3 | V5 子电路 677 板 | 人类布局（开源板裁剪，保持原样） | 真实 | **全真实** |
| L2 | 裂变变体 96 板 | **SA 复合 cost 重优化**（非人类手摆） | 真实（真实板克隆） | 半真实（可选） |

**结论：不用任何合成数据完全可行**——L1+L3 已提供 682 块全真实板，且 L3 实测
旋转分布天然均匀（见 4.3），合成模板生成器（V3）从方案中移除，仅作日后
"受控难度课程"的备选保留。L2 是否启用取决于你对"布局非人类手摆"的接受度：
它的价值是给稀有的真实结构造近优变体；若坚持只用人类布局，L2 跳过，L3 放量即可。

### 4.0 前置：JSON 板加载兼容层（0.5 天）

DT 的板子全部是 `boards_json` 格式（board_bounds / components[bbox, rotation, nets,
pins, footprint_w/h, is_fixed…] / nets），与 DQN mock 模式同源（ran-pang.json 双方通用已验证）。
需要：

1. 新建 `scripts/generate_expert_from_json.py`：从板 JSON 构造 PCBLayoutEnv（mock 路径，
   无需 KiCad）→ 调 `generate_and_save_expert_transitions()`；
2. 兼容性自检脚本：对每块板断言
   （a）pins 相对偏移与 bbox 朝向一致（DT V3 板的 pins 已旋到专家朝向，DQN 侧统一按
   "pins 相对当前 bbox" 约定重算一遍）；
   （b）元件数 ≤ MAX_MOVABLE(18)、有效网格 ≤ GRID_W/H(100)；超限板跳过并记录；
   （c）专家轨迹生成后负样本率 = 0%（沿用现有检查）。

### 4.1 L1：五块真实板全量（0.5 天）

现有 `generate_expert_only.py` 逐板执行（KiCad 路径）：

```powershell
$env:KICAD_PATH="D:\pcb大模型\kicad"
python generate_expert_only.py --board 灯板2      # Chip×4+焊盘×2，碰撞形态最丰富
python generate_expert_only.py --board Connector
python generate_expert_only.py --board Button
python generate_expert_only.py --board 按键侧板
```

`admin.txt` 的 GRID 100×100 / MAX_MOVABLE=18 已罩住全部 5 板（0.2mm 下最大 55×55 格）。
每板 20000 条不变。这一层验证"多板管线"本身。

### 4.2 L2：人类锚点裂变板（1 天，DQN 侧零新算法）

DT 的 `augment_from_human.py` 已经实现"克隆真实板 → 同封装换位 / ±90° 旋转 / 整簇平移 /
信号网交换 → **合法化兜底 → SA 复合 cost 重优化** → 合法近优变体"（96 块已落盘
`boards_json_aug/`）。这正是 DQN 侧"近优变异"想要的产物，且质量更高：

- DQN 现在的变异：盲 ±1~2 格，**必然更差**，只查合法性；
- DT 裂变板：扰动后经 SA 重优化，**合法且接近该结构下的 cost 最优**。

动作：经 4.0 兼容层把 96 块变体板灌入 DQN，每板生成 1000~2000 条专家 transition。
预期收益：解族从 1 个 → 96+ 个，且每个变体保留真实板结构（电源网/去耦对/固定件）。

### 4.3 L3：V5 真实子电路 677 板（2~3 天，主力增量，**零合成数据**）

`DT测试/data/boards_json_subcircuit_train/`（另有 eval/test 划分勿动）是 V5 从开源
KiCad 项目裁剪的**真实人类布局子电路**。这是全工作区唯一的"真实人类布局规模化"数据。

**2026-08-30 实测可用性（677 块训练板全量扫描）**：

| 检查项 | 结果 |
|---|---|
| DQN 约束通过率（movable≤18、0.2mm 网格≤100×100） | **677/677 = 100%**（0 块超限） |
| 旋转分布（2764 个可动元件） | 0°=26%，90°=25%，180°=23%，270°=24%——**天然均匀** |
| 含 90°/270° 放置的板 | 577/677（85%） |
| 长条元件（宽高差>15%） | **2419/2764（87.5%）** |

对比现有开关小板专家数据（旋转 90% 黏滞、100% 正方形元件）：**V5 真实数据在旋转多
样性上比任何合成方案都好，且无需造景**。这直接解除对 V3 合成模板生成器的依赖。

动作：

1. 经 4.0 兼容层批量自检（约束过滤已实测 100% 通过，剩余检查为 pins 朝向与
   专家轨迹生成后的四道门禁）；
2. 分批生成专家 transition，**每板 300~500 条**（子电路小，几百条足够）；
   首批建议 50 板 × 400 ≈ 2 万条与现有 buffer 预算对齐，验证管线后放量到 200+ 板；
3. 数据预算重构：`EXPERT_TOTAL_TRANSITIONS=20000` 的语义从"单板总量"改为
   **"训练时每 episode 随机抽板、专家池按板均衡采样"**。实现：
   - `ExpertReplayBuffer` 加"按板分桶采样"（专家区按板 id 分桶，每 batch 各板均匀出样，
     防止大量小板互相淹没）；
   - 配置改为 `EXPERT_PER_BOARD=400`、`EXPERT_BOARDS_MAX=50`（首批），
     总池 ≈ 2 万，buffer 容量公式不变（5× 池大小）。

### 4.4 数据验收门禁（移植 DT 的质量纪律）

每批数据落盘前过四道门（新建 `scripts/check_expert_data.py`，一个参数指定目录批量跑）：

1. **零负样本**（现有检查，reward min ≥ 0）；
2. **合法性全查**：重放每条轨迹的最终布局，逐元件查越界/硬重叠/keepout
   （复用 `PCBUtils`，参照 DT `augment_from_human.py` 的独立 reload 校验）；
3. **结构统计**：旋转分布（90°/270° 占比 ≥10% 为达标线）、每板落点覆盖率、
   不同最终布局数的真实去重（按构型聚类而非坐标精确匹配）；
4. **跨源均衡**：L1/L2/L3 三源在池中的占比与采样权重记录进 `training_summary`。

## 5. P2 方法层修正（与 P1 并行）

### 5.1 地基实验 E1：当前 reward 下人类布局天花板 vs 纯 RL 天花板（1 天）

- 无变异专家轨迹：`EXPERT_*_NOISE_PROB=0`、`EXPERT_EPSILON_DECOMPOSE=0` →
  `generate_expert_only.py` 生成确定性轨迹，聚合 = 人类天花板（校准后口径）；
- 对照：`run_exp.py --tag base_now`（纯 RL 10k，当前 reward）取 best；
- **判定**：人类天花板 ≥ RL best − 5 → λkl 恒定锚定合法；否则 → 5.3 退火方案。

### 5.2 地基实验 E2：BC-only 贪心基线（1 天）

- `run.py` 加 `--bc-only`（Phase 1 后直接把 `bc_pretrained.pt` 存为最终模型，跳过 Phase 2）；
- `scripts/eval_greedy.py`（见 P3）对 BC-only 与 T3 的 RL 模型各评 10 个贪心 episode；
- **判定**：BC-only 放满率 ≥90% 且步数 ≤ 2×T3 → 部署走 BC-only，Phase 2 只用于冲质量场景。

### 5.3 λkl 定稿与（视 E1 结果的）退火

- T3(λkl=10) vs T5(5)：各 3 seeds × 10k epi × 10 贪心 episode，方向一致才定稿；
- 若 E1 判专家次优：`λkl(t) = max(2, 10 × (1 − t/5000))`（前 5000 ep 锚稳定，后放开超越），
  `λv=10` 恒定保 Q 幅度。实现：`run.py` 每 episode 更新 `agent.bc_reg_lambda`（约 5 行）。

### 5.4 重叠感知动作 mask（治贪心死循环的根）

`_build_mask_for_step(1/2)` 对候选格做 AABB 预检（当前板 36×36×6 可负担；大板可隔行采样预筛），
必然硬重叠/出界的格直接 mask。T1 式死循环（957 步 −17659）从机制上杜绝，
不再依赖 λkl 压制。验收：λkl=100 的旧失败配置 + mask 后贪心不再死循环。

### 5.5 share_weights 消融

[0.2,0.3,0.3,0.1,0.1]（现状）vs [0,0,0,0,1]（仅末步）vs [0.2]×5（均匀），
3 组 × 5k epi。专家与 RL 两侧同步改（`run.py:384` 与 `_build_step_transitions` 同源）。

## 6. P3 评估协议

1. 新建 `scripts/eval_greedy.py`：加载 checkpoint → ε=0.15 跑 N=10 episodes →
   输出 R / steps / placed / 放满率的 mean±std（JSON + 控制台表格）；
2. **主指标 = 贪心三件套**（贪心 R、放满率、步数），训练 mean R 降级为发散监控
   （1000 ep A/B 已证明极简板上训练均值无区分度）；
3. 新增双轴评估（借 DT 侧思想）：物理项（硬重叠数/软间距总量）+ 结构项
   （去耦对距离、同网聚合度）分列报告，不再汇成单一 reward 看不懂差在哪。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| DT 板 JSON 与 DQN mock 格式细节不一致（pins 朝向、字段缺省） | 4.0 兼容层 + 自检先行，先跑 3 块板试点再放量 |
| V5 子电路小板太多淹没大板 | ExpertReplayBuffer 按板分桶均衡采样（4.3） |
| 修复旋转 bug 后旧数据/模型全部作废 | 正方形板回归对照证明管线等价；反正 P1 就要重生成 |
| 专家池变大后 BC 预训练变慢（50 epoch × 池大小） | BC 每 epoch 随机抽 2 万条（现成 DataLoader 改法），不动池 |
| λkl 退火后 Q 发散回归 | λv=10 恒定保底；退火期 loss 监控告警回滚 |
| 近优变异/裂变仍不含真实"设计意图" | L3 真实板本身就是人类意图；结构项双轴评估验证（P3-3） |
