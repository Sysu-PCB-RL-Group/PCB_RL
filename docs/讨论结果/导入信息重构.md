### 0.3 三条硬规则（= 任务的"合法域"，与 §0.4、§11 一起构成完整任务定义）

```text
硬重叠 A  pad ↔ pad    ：同层 ∧ 不同 footprint ∧ AABB 相交(gap<0) ∧ 【不看 net】
硬重叠 B  pad ↔ via    ：同层 ∧ AABB 相交 ∧ 双方 netcode≠0 ∧ netcode 不相等
硬重叠 C  pad ↔ 禁布区  ：同层（开槽视作 F/B 两层通用）∧ AABB 相交 ∧ 排除禁布区项所属 footprint 的 pad

软间距 S1 pad ↔ pad    ：跨封装 ∧ 同层 ∧ 不看 net ∧ 0≤gap<0.2
软间距 S2 pad ↔ via    ：同层 ∧ 双方 netcode≠0 ∧ 不相等 ∧ 0≤gap<0.2
软间距 S3 pad ↔ 禁布区  ：同层（开槽两层通用）∧ 排除所属 footprint ∧ 0≤gap<0.2

出界                   ：footprint 的 pad ↔ 板框（pad 的 AABB 越出板框即违规，不管 net）

统一口径：几何一律 AABB ｜ 同一对只计一次 ｜ 硬重叠阈值 gap<0（相切不算）
         层只判 F.Cu / B.Cu 的共享层（PTH 覆盖两层；开槽视作两层通用）
```

> ⚠️ **2026-09-17 澄清（重要）**：以上只是"**合法域**"。**"不符合人类布局经验"≠ 违规** ——
> 去耦电容不贴 IC、安装孔摆放随意、差分对不等长……这些属于**未建模的人类经验**，
> **既不影响合法性、也不进目标**（详见 §11 范围声明）。

## 1. 数据事实与单位

> 这些事实是**全部判定的依据**。来源：pcbnew 10.0.4 + 20 板实测（只读探针）。

### 1.1 数据源与"EasyEDA 导出"的四个表示层特征

数据源是 **20 块 EasyEDA Pro 导出的 `.kicad_pcb`**（每块板配套一份 `.kicad_pro`）。规模：**858 footprint / 3780 pad / 3422 via**；2 层板 15 块、4 层板 5 块。

导出过程带来 4 个**表示层**特征（不是设计错误）：

| # | 特征 | 实测 | 对建模的影响 |
|---|---|---|---|
| 1 | **一个物理焊盘/孔被拆成多条同号 pad 记录** | PID `H1`（`m3 125x300`）文件里就是 **7 条 `pad "1"`**：1 个 `6.5×6.5 / drill 3.18` 大盘 + 6 个 `1.016×1.016 / drill 1.021` 小盘（中心距原点 2.4~2.55mm，**全部落在大盘内**） | **同一 footprint 内部会重叠** ⇒ 判定必须排除同 footprint |
| 2 | **存在"无铜的 pad"（环宽 ≤ 0）** | 全板 **28 个**（PID 24、lr1388 4），如上面那 6 个小盘 `size 1.016 < drill 1.021` ⇒ 其实是"孔"不是铜 | "pad = 铜"在部分数据上不成立（不特判：它们参与跨封装重叠 = 0 例） |
| 3 | **大量焊盘/过孔未赋 net** | **pad：619 / 3780 = 16.4%**；**via：24 / 3422 = 0.7%**（其中 3.5mm×8、2.4mm×2 是"机械孔被导成 via"） | 决定 net 过滤怎么写（§3.2/§3.4） |
| 4 | **铜箔被导成绘图线段** | 板级铜图形 **491 个**（climbsnail 473、wzh 15、300W 3）：F/B 上的 `SEGMENT`/`ARC`；另板级丝印 488 个 | 它们**不是** track/zone ⇒ 与"不纳入走线/铺铜"一同排除（否则与可动 pad 冲突 293 例） |

**同封装内部重叠的完整账**：

```text
同封装内部 AABB 重叠 = 691 对（同层 ∧ 同一对只计一次；按层计数 957 对）
真实相交 = 336 例（9 块板）；AABB 重叠出现在 11 块板
成因三类：① 同号多 pad（m3 铜柱、半孔排针"槽+孔"、安装孔）
          ② DFN/QFN 中心散热盘压引脚盘（MiniMos U9#9 大盘 × #5~#8）
          ③ 连接器壳盘群（300W XT30 J3#A1×#B12、USB-C USB1#A1B12×#A4B9）
```

⇒ **判定必须显式排除"同一 footprint 内部"**：不是"它们不会重叠"（会），而是"**这些相对位置由封装固定、RL 改不动**"，判它既无意义也无解。

### 1.2 旋转

| 项 | 事实 / 规则 |
|---|---|
| 文件与 API | footprint `(at X Y [角])`；`GetOrientationDegrees()` 与文件 **1:1 不量化**（45/−45/135 全保留）；45° 丢失**只**来自旧的 `round(deg/90)%4` |
| **`(at X Y)` = 锚点 = 旋转中心** | `GetPosition()`；实测把 θ 改成 0/90/180/270 时 `GetPosition()` 恒定、pad 与 hull 绕它转（U8 锚点离 hull 中心 12mm，转 180° 后 hull 中心跑到另一侧 24mm 外） |
| **换算公式（已验证，刚体）** | `板坐标 = 锚点 + R(−θ)·局部`，即 `x' = x·cosθ + y·sinθ`、`y' = −x·sinθ + y·cosθ`（Y 向下）。逆变换 `局部 = R(+θ)·(板坐标 − 锚点)`。实测 hull 顶点与 pad 位置**最大误差 0.0000mm**（误用 `R(+θ)` 时误差 1.4~24mm） |
| pad 角度语义 | `GetOrientationDegrees()` / 文件字段是**板坐标下的绝对朝向**；相对角走 `GetFPRelativeOrientation()` |
| 镜像 | `Flip(leftRight=False)` ⇒ 局部 x→−x 且 θ 0→180；`Flip(leftRight=True)` ⇒ 局部 y→−y 且 θ 不变。**用上面的公式无需额外取反** |
| **非正交原件（16 个）** | 15 个 ±45°/±135° 等距点 + 1 个非等距（lyg0927 `X1 = −0.62°`，全数据集唯一）；分布：MiniMos `U15`；Mini控制板 `C13/U14/U16/R36/SW1`；esp32s3r8n8 `C19/C47/C50/L6/U3/L4`；gd32vw553 `C55/U1`；lyg0927 `U1/X1` |

**决策（Owner 拍案）**

```text
① 角度取值集合保持 4 值 {0°, 90°, 180°, 270°}；导入时同时保留
   · 原始角度（文件真实值，含 45°，仅用于排查）
   · 转换角度（建模与导出都用它）
② tie 规则：等距时一律"按数值降级"（取数值更小的一档）
   45 → 0、135 → 90、−45 → −90(≡270)、−135 → −180(≡180)
   非等距按"最接近"（本数据集唯一例：lyg0927 X1 −0.62° → 0°）
③ 导出写回"转换角"；原始角度不参与导出
④ 落地表示：角度内部用 `{0,1,2,3}` 索引，语义层仍是角度；原始角度另存 float
⑤ 底层/翻面按 pcbnew 原意，不自定义角度语义；算位置时必须注意旋转方向
```

**选用原因**：`{0,90,180,270}` 是既有动作空间的既定取值且量化误差可控；"按数值降级"保证等距点有唯一归属；导出必须与模型几何一致。
**已知后果（接受）**：导出成品会把这 16 个非正交件的姿态归到 90° 倍数（单个最多改 45°）；**实测位移**（probe154，KiCad 本体：raw 角姿态 vs 转换角姿态）**焊盘最多移动 3.87mm**（lyg0927 `U1`；SW1 3.10、U3 3.28、U14 2.56、U15/U16 1.94、C13 0.42、`X1` 0.015）——这就是"归一化改变几何"的真实量级，也是硬重叠 B 17→36 / C 0→4 / S1 8→5 的来源（验收见 §5.3⑥ 旋转专项；16 件清单见附录 A probe154/155）。

**⚠️ 与判定的强关联（probe80 实测）**：**非正交旋转会让 AABB 撑到 √2 倍**（产生假阳性），而"转换角归一化"会让这些焊盘**真的移动**，两个方向都要算清：

- **假阳性消失**：`U16#1×FPC1#6`（原 AABB 相交 −0.12mm、真实距离 +0.44mm）在转换角下不再相交；软间距 S1 由 8 例降到 **5 例**；
- **但归一化也会把焊盘搬到固定对象正上方**：硬重叠 B 由 17 例（多 AABB 假阳性）变成 **36 例真重叠**，硬重叠 C 由 0 变成 **4 例**；
- ⇒ **判定必须用"转换角几何"（= 转换数据里存的那份）**，否则既会冤枉合法布局、也会漏掉真实重叠。

### 1.3 footprint 尺寸口径

| 口径 | 含义 | 实测覆盖 | 本项目的用法 |
|---|---|---|---|
| **`GetBoundingHull().BBox()`** | 板坐标 AABB（焊盘 + 封装图形，不含位号/值文本） | 100% | **采用**（旋转后仍实时正确） |
| `GetBoundingBox()` | 同上，但**是缓存**，旋转后不刷新 | 100% | 不用 |
| `GetCourtyard(F_CrtYd)` | 人工画的"实体+公差"代理 | 90.6%（777/858） | 不用（覆盖不全，且不是制造硬约束） |
| `GetFpPadsLocalBbox()` / `GetLayerBoundingBox(LSET)` | 局部 / 按层 | 100% | 仅排查用 |

**决策**：footprint 尺寸保留 **hull 现状**，**接受它包含 `User.*` 等导入杂物**（如 U8 hull 29.21×28.45 实际来自 `User.Drawings`）。
**选用原因**：覆盖 100% + 旋转实时正确 + 零额外实现。
**已记录的后果（接受）**：`User.*` 杂物会撑大 hull；但 **hull 不参与任何判定**（§1.9），副作用只影响"占位/展示"。

### 1.4 层

| 项 | 事实 |
|---|---|
| 元件所在面 | **只有 F.Cu 802 / B.Cu 56**，**没有任何元件在内层** |
| pad 层集合 | 由 pad attribute 决定：**SMD 3022**（单面：F 2755 / B 267）、**PTH 758**（跨该板全部铜层） |
| **"贴片焊盘面 ≠ 元件面"的 5 个实例** | 3 个整体错位（elisaday `U15` 在 F 面但 13 个 pad 全在 B；verysunshine `U10` 2 pad 在 B；verysunshine `U3` 在 B 面但 2 pad 在 F）+ 2 个两面混合（wzh `USB1/USB2` 各 9 pad 在 F、9 在 B） |
| Save→Reload | pad 的层声明**原样保留、未被归一化** ⇒ "pad 独立记录层"既必要又可靠 |

**决策（Owner 拍案）**：**层的讨论范围 = 仅 `F.Cu` 与 `B.Cu`**（其他层一律不管）；**pad 独立记录所属层**（`{F}` / `{B}` / `{F,B}`，PTH 两值全含，**以源数据为准**）。
**新规定（2026-09-16）：动作空间不含"层动作"** —— 选中某个 footprint 时，它**只能在自己原本的层里活动**（不能自选层、不能跨层移动）⇒ footprint 与 pad 的层永远等于导入时的记录事实，判定侧"同层"匹配**不需要任何换算**。
**选用原因**：① 从根上保证"层信息不翻转"（上述 5 个"面不一致"实例永远是静态事实，不需要"以谁为准"）；② 复刻/布局任务的自由度本来就是"平面内移动 + 旋转"，换面不是这个任务的维度；③ 让"跨层移动"在模型里**不可表示**（而不是靠运行时检查）；④ 判定只涉及铜层"同层"匹配，内层/Mask/Paste/丝印/Fab/CrtYd/User 全都不参与 ⇒ "内层规则区是否生效""PTH 要不要裁剪 In1..In30"等一串问题自然消失。
**与状态的关系**：`L`/`G` **不按层拆表**（每个旋转各一张），层语义在 `L` 内部按 pad 层过滤（→ §5.6）。

### 1.5 板框与开槽

| 项 | 实测 |
|---|---|
| API 坑 | `GetBoardPolygonOutlines(poly, aInferOutlineIfNecessary)` **第 2 参必传**；18/20 板传 `False` 即得 1 个闭合轮廓；**300W、gd32vw553 返回 False**（300W 左边有 ~13mm 缺口不闭合）⇒ 需传 `True` |
| **板轮廓内孔（开槽）** | **45 个 / 13 块板**（300W 9、lyg0927 8、climbsnail 4、lr1388 4、verysunshine 4，其余各 2）；最大 2.99×2.99mm |
| **这 45 个孔的来源** | **全部来自"封装内嵌的 Edge.Cuts 图形"** —— `GetBoardPolygonOutlines()` 会自动把封装内嵌 Edge.Cuts 并入板轮廓（去重 bbox 比对：45/45 完全重合） |
| 封装内嵌 Edge.Cuts 图形 | **48 个 / 13 块板**（45 个闭合 POLY + 3 个开口 SEGMENT）；`board.GetDrawings()` 看不到，必须遍历 `footprint.GraphicalItems()` |
| 板级 Edge.Cuts 图形 | Line 28 / Rect 14 / Arc 13（线宽 0.254 居多）——**板框的来源** |
| 挂在 Edge.Cuts 上的规则区 | 6 个（300W 2、travellium 4）—— 属"规则区"，见 §0.4 不纳入 |

**决策（2026-09-16 收口）**

```text
① 转换数据里的"板框" = 一个 AABB（GetBoardPolygonOutlines 结果的外接矩形），不做尺度内缩
   内缩属 env 层：valid_area = bbox 各边内缩 BOARD_MARGIN（默认 0 = 不内缩）
② 板框的原始几何只留在 raw：Edge.Cuts 图形清单（板级 + 封装内嵌）、多边形外轮廓与孔顶点、
   edges_bbox（含线宽）、inferred 标志 —— 访问器 = KiCadUtils.get_raw_board_outline()
③ 45 个内孔 = 禁布区的一部分（几何取 AABB），开槽视作 F/B 两层通用
```

**选用原因**：① 出界判定只需回答"pad AABB 是否越出板框"，AABB 足够且零歧义（开槽已由禁布区单独覆盖，实测两者的孔完全同一批 ⇒ 不会漏判）；② **不内缩** = 与人工布局的实际口径一致（`BOARD_MARGIN = 0`；若按原生 `copper_edge_clearance = 0.5` 内缩，参照越界会更多，属另一套标准）；③ 原始几何留 raw 供排查/可视化。
**实测（probe79）**：`raw.polygon_bbox` 与转换 `BoardOutline.bbox` **完全相等**；`edges_bbox` 含线宽故每边大 0.127mm；`valid_area(margin=0)` 与 bbox 相同；raw 的板级 Edge.Cuts 1 个 + 封装内嵌 2 个 ⇔ 转换侧 `slots = 2`（同一批对象）。

### 1.6 KiCad 规则区（rule area）——**不参与任何判定**

- pcbnew 里是 `ZONE` 的 rule area（`zone.GetIsRuleArea()`）：20 板共 **133 个**（9 块板），**133/133 flag 组合完全相同** = `(禁过孔, 禁走线, 禁焊盘, 不禁元件, 禁铺铜)`；层分布 F.Cu 66 / B.Cu 47 / In2 10 / In1 4 / Edge.Cuts 6。
- **实测：人工布局本身就"违反"它们** —— 按"pad 中心落在真实多边形内 + 层匹配"统计：**46 个规则区（35%）压到 ≥1 个 pad**、同层违规配对 **286**、**40 个规则区压在元件锚点上**。
- 文件原文（300W）：`(keepout (tracks not_allowed) (vias not_allowed) (pads not_allowed) (copperpour not_allowed) (footprints allowed))` —— 字面禁焊盘但**允许放元件**，组合自相矛盾，133 个全是同一组合。
- **推断**：这是 EasyEDA 的"禁铺铜区"被统一翻译成"KiCad 全禁（除元件本体）"的副产品，**不是设计者真的想禁焊盘**（`.kicad_pro` 里 `drc_exclusions` 为空，说明设计者既没遵守也没豁免）。
- **决策：规则区不参与任何元件/焊盘判定**，只留在原始数据里备查。
- **选用原因**：① 133 个里"禁止 footprint" = **0 个**、"placement area" = **0 个** ⇒ 没有任何"禁止元件放置"的语义；② 若当硬约束用，等于宣布"人工参照布局本身违规（35% 冲突）"，而参照是专家轨迹的来源。
- 附：**KiCad 官方 DRC 不可用** —— Python 侧只有模块级 `WriteDRCReport()`，调用后在 C++ 层 assert 杀进程（`Boolean ops on curved polygons are not supported`）⇒ 只能自算。

### 1.7 `.kicad_pro` 原生规则（20 板取值完全一致）—— 阈值标定依据

**① `board.design_settings.rules`（19 条，mm，节选关键项）**

| 字段 | 值 | 语义 |
|---|---|---|
| `min_clearance` | **0.0** | ⚠️ **不是实际间距**，只是"自定义规则里 clearance 的取值下限" |
| **`min_copper_edge_clearance`** | **0.5** | **铜到板边**（含板框与开槽）最小间距，DRC = **error** |
| `min_hole_clearance` | 0.25 | 孔到其它铜的最小间距（error） |
| `min_hole_to_hole` | 0.25 | 孔到孔边缘最小间距（warning） |
| `min_via_diameter` / `min_via_annular_width` / `min_through_hole_diameter` | 0.5 / 0.1 / 0.3 | 过孔外径 / 环宽 / 通孔钻孔下限 |
| `min_track_width` | 0.2 | 走线宽下限（error） |
| `min_connection` / `min_groove_width` / `min_silk_clearance` / `solder_mask_to_copper_clearance` | 0.0 | 细颈 / 铣槽 / 丝印 / 阻焊 |
| `min_resolved_spokes` | 2 | 散热焊盘最少辐条数 |
| `max_error` | 0.005 | 多边形近似精度 |

**② `net_settings.classes`（只有 1 个类 `Default`，`netclass_patterns` 为空 ⇒ 所有网络都用它）**

| 字段 | 值 | 语义 |
|---|---|---|
| **`clearance`** | **0.2** | **铜-铜最小间距 = DRC 真正使用的值，且只在"不同 net"之间要求** |
| `track_width` / `via_diameter` / `via_drill` | 0.2 / 0.6 / 0.3 | 默认走线宽 / 过孔外径 / 钻孔 |
| `diff_pair_gap` / `diff_pair_width` / `diff_pair_via_gap` | 0.25 / 0.2 / 0.25 | 差分对 |
| `bus_width` / `wire_width` | 12 / 6 | **画图宽度，不是 PCB 约束** |

**③ `rule_severities`（62 条 DRC 严重级别，与我们有关系者）**

| 级别 | 规则 |
|---|---|
| **error（硬）** | `clearance`、`copper_edge_clearance`、`hole_clearance`、`shorting_items`、`items_not_allowed`、`courtyards_overlap`、`annular_width`、`track_width`、`unconnected_items`、`zones_intersect`、`invalid_outline` |
| **warning（软）** | `silk_over_copper`、`silk_overlap`、`silk_edge_clearance`、`hole_to_hole`、`connection_width`、`copper_sliver`、`padstack`、`isolated_copper`、`duplicate_footprints` |
| **ignore** | `footprint_filters_mismatch`、`footprint_type_mismatch`、**`missing_courtyard`**、`track_not_centered_on_via` |

**三条语义结论（直接支撑我们的设计）**

1. **间距只在"不同 net"之间要求**（同 net 的铜本来就该连在一起）⇒ 原生背书"判定必须排除同 net"（我们据此放行 948 例 in-pad via）。
2. **丝印类违规全部是 warning** ⇒ 原生语义里丝印干涉**不是硬约束**（支持"丝印可以出板框"）。
3. **`missing_courtyard = ignore`** ⇒ 不强制 courtyard 存在（与 90.6% 覆盖相符）。

### 1.8 fixed：**数据里根本不存在** ⇒ 本项目不再定义 fixed

| 检查层 | 结果 |
|---|---|
| **文件原文关键词**（20 块板全文） | `(locked` = **0**、`(attr ` = **0**、`board_only` = **0**、`dnp` = **0**、`exclude_from_pos_files` = **0** |
| API（24 个候选方法） | `IsLocked()` / `IsPlaced()` / `NeedsPlaced()` / `IsReplaceable()` / `IsExcludedFromPosFiles()` / `IsDNP()` / `IsExcludedFromBOM()` / `IsBoardOnly()` ⇒ **858 个全是 False** |

### 1.9 判定对象（Owner 规定）

| 判定 | 判定对象 | 说明 |
|---|---|---|
| 硬重叠 / 软间距 | **pad 的 AABB ↔ pad / via / 禁布区的 AABB** | 贯穿焊盘（PTH）在 F/B 两层都参与 |
| 出界 | **pad 的 AABB ↔ 板框** | **丝印等非焊盘元素允许出板框** |
| footprint `hull` | **不参与任何判定** | 只作为 footprint 的"占位/展示"口径 |

**选用原因**：① 铜/电气一类的硬约束，**焊盘是唯一可靠载体**（`User.*` 是导入杂物、丝印可故意超出、courtyard 只有 90.6% 且是人工代理）；② 顺带消除"`User.*` 撑大 hull 导致过度保守"的问题；③ 这也是**取消 package_type** 的直接理由（判定只看焊盘，footprint 语义分类再无消费方）。
> 备查实测：`GetAttributes()` 858 全 0；`GetLikelyAttribute()` 100% 有值（SMD 747 / THT 110）；`GetComponentClass*` 全空串；`pad.GetPinType()` 全空；`pad.GetProperty()` 全 `NONE`。

### 1.10 单位与精度下限（2026-09-16 实测 + 修 bug 得到）

- pcbnew 的**内部计数单位是整数纳米**：`pcbnew.PCB_IU_PER_MM = 1e6`（`FromMM(1.0)=1000000`、`ToMM(1)=1e-06`）；`GetPosition()` / `GetSizeX()` / `GetDrillSizeX()` 全部返回 **nm 整数**；mm 只出现在三处：① Python 桥接 `ToMM/FromMM` ② `.kicad_pcb` **文件文本**（mm，≤6 位小数）③ GUI 显示。
- 本项目口径：**raw = nm 整数；转换数据 = mm 浮点**（§4 硬要求 2）。
- ⇒ **任何阈值 / 容差不得细于 1 nm（1e-6 mm）**：位置只能落在整数 nm，而 hull 中心可落在**半 nm**（实测 `hcx % 1 == 0.5`）⇒ 任何"按中心重定心"必然带 ≤1 nm 量化偏差。
- **反例（已修）**：上一代测试 `tests/kicad/test_pin_rotation.py` 原写 `abs(dy) < 1e-6`（恰好等于 1 个量子）⇒ 源姿态偏差 0 而其它 3 个姿态恒为 **1 nm** ⇒ 卡边界必炸；当时改为**按 nm 整数比较**。（⚠️ 该文件属**上一代 KiCadUtils 接口测试**，已随 2026-09-18 测试清理删除——副本见 `.codebuddy/artifacts/legacy_tests_backup/`；现行坐标/旋转覆盖在 `tests/kicad/test_pcb_model_positions.py`（误差判据 1nm）。）

### 2.1 footprint = **至少含一个 pad 的封装**

| 项 | 实测 |
|---|---|
| 总数 | **858**，其中零 pad 的 **1 个**（PID `U11` = `TT马达`） |

### 2.2 pad = **属于 footprint 的 pad**（独立焊盘不考虑）

| 项 | 实测 |
|---|---|
| 总数 | **3780**（全部属于 footprint） |
| **独立焊盘** | **0 个**（`board.GetPads()` 3780 个逐个 uuid 比对，全部能在 footprint 内找到；文件顶层 `(pad …)` 计数 = 0） |

| `netcode=0` 的 pad | **619 个（16.4%）**，分布在 112 个 footprint（**全 pad 无 net 的 8 个** + 部分无 net 的 104 个） |
| **是否裁剪** | **不裁剪** —— 619 个 net0 pad 全部进模型；net 只作为**判定条件**，不作为建模裁剪条件 |

**选用原因（不裁剪）**：① 裁掉 net0 pad 会形成**盲区**（可动件的无 net 大铜皮可随意压别人，实测这些区域最高占板面 23.58%）；② 还会连带引出"零 pad 的 footprint"问题（那 8 个机械件的 pad 全无 net）与额外的禁布区需求；③ 保留的代价只有 1 例 AABB 假阳性。
**⚠️ 实现坑**：判断"pad 是否属于 footprint"**不能用 `isinstance(pad.GetParent(), pcbnew.FOOTPRINT)`**（本 SWIG 下 3780 个全判 False）⇒ 用 **uuid 比对**或数量差。

### 2.3 via = **全部纳入，含无 net 的**

| 项 | 实测 |
|---|---|
| 总数 | **3422**（全部 through）；模型允许 `layers` 为空集（埋孔/盲孔）⇒ **空集 = 不在 F/B、不参与 F/B 判定**（不捏造层归属） |
| `netcode=0` | **24 个**：直径 **3.5mm×8、2.4mm×2、0.61mm×14** |
| 其中 10 个"大孔"的真相 | 文件原文 `(via (at …) (size 3.5) (drill 3) (layers "F.Cu" "B.Cu") (net "") …)` ⇒ **EasyEDA 把机械孔/安装孔导出成了 via**（2 个 `size 2.4 / drill 2.4` 环宽为 0，物理上不可能是过孔）；它们不与任何 pad 同心、也不与板轮廓的孔重合 |

**选用原因**：① 它们都是"板上真实的孔/铜"，作为障碍参与判定是物理正确的（机械孔处不能放 pad）；② 统一纳入避免为"假 via"单开一条规则。

### 2.4 禁布区 = `{TT马达 hull} ∪ {板轮廓的 45 个开槽}`

```text
成员一：TT马达（PID U11）的 hull  → 1 个，64.25×26.15mm = 1680mm²（PID 板面 20.6%）
成员二：板轮廓的 45 个开槽        → 几何取 AABB；开槽视作 F/B 两层通用
判定  ：pad ↔ 禁布区（同层 ∧ AABB 相交）∧ 排除禁布区项所属 footprint 自己的 pad
owner_ref 取值域 = { footprint 的 ref（含合成 @库名#序号）} ∪ { zero_pad_footprints 的封装名 }
                   （例：motor_hull 的 owner 是 U11 = 零 pad 封装，故不在 footprints 里）
                   ⚠️ 两处 ref 必须用同一套合成规则，否则"排除自家槽"会静默失效
```

> ⚠️ **口径 (A)（2026-09-18 裁决，probe169）**：45 个开槽**属于封装、随 footprint 移动/旋转**（KiCad 本体：平移带槽件时板轮廓内孔跟着动），**未放置件的槽不在板上**。落地 = `pcb_model.state_keepouts(model, placed)`（静态禁布区恒在场 + 仅已放件的槽位姿化）；`legal_masks`/`lookahead_mask` 默认即用它，`Judge` 用 `placed=` 参数（缺省 = 全体在源位姿的参照口径）。详见 §0.6 p。

**选用原因**：① `TT马达` 已不是 footprint ⇒ 只剩"实体占位"这一层语义，必须靠禁布区表达（否则 RL 可以把元件摆到马达上而无人拦）；② 45 个开槽是"元件自带的开槽"（USB 口、开关定位柱），物理上不可放置；③ 顺带补上"出界用外接矩形口径看不见开槽"的漏洞。
**⚠️ 实现坑**：**开槽必须带归属** —— `poly.Hole()` 会丢失"这个槽属于哪个 footprint"，导致"自家槽"被当成外部障碍（实测多出 2 例假阳性）。做法：用 `fp.GraphicalItems()` 里 layer==Edge.Cuts 的图形（天然带归属），或对 `poly.Hole()` 按 bbox 做归属匹配（45/45 完全重合）。

**"机械/结构特征"在数据里有三种表示法**（禁布区概念的由来）：

| 同一类东西 | 表示法 | 处置 |
|---|---|---|
| 马达实体 | **零 pad 的 footprint**（`TT马达`） | → 禁布区成员一 |
| 安装孔 / 定位孔 | **`via` 且 `net=""`**（10 个） | → 已归入 via 类（§2.3） |
| USB 口 / 开关定位柱开槽 | **封装内嵌 `Edge.Cuts` 闭合图形** | → 禁布区成员二 |

## 3. 违规标准与判定器

> 判据的**形式化定义**在 §0.3；本章给出**每条的选用原因、参照诊断、实现口径与验收**。
> 全部判定 = "**硬约束、严格、无豁免、无白名单**"（见 §3.6 标准设计原则）。

### 3.1 硬重叠 A：pad ↔ pad

```text
同层（F.Cu/B.Cu 共享层）∧ 不同 footprint ∧ AABB 相交(gap<0) ∧ 【不看 net】
同一对只计一次；相切(gap=0)不算
```

**为什么"不同 footprint"是硬条件**：同封装内部 AABB 重叠 **691 对**（同层去重；按层计数 957；真实相交 336），来自"导出把物理焊盘/孔拆成多条同号 pad"（§1.1）；这些相对位置**由封装固定、RL 改不动**。不排除 ⇒ 参照布局凭空多 336~957 例，且不可能通过移动元件消除。

**为什么不看 net**（关键取舍）：
- **动机**：若要求"net 相同才豁免"，RL 就能把两个元件的**同 net 焊盘整片叠在一起**（实体必然相交）而不受罚——参照板里就有 3 例这样的真实重叠（`D3#1×D2#1`、`@Pad_e377#1×CN3#2`、`C16#2×USB1#9`，都是"共焊盘/加宽"写法）。
- **代价**：参照自身有 **4 例**跨封装重叠（转换角几何）：Mini控制板 `D3#1×D2#1`（−0.2970）、`C10#2×U14#3`（−0.2225，`U14` 原始角 −135° 归一化后压到隔壁电阻盘上）、300W `@Pad_e377#1×CN3#2`（−0.4305）、verysunshine `C16#2×USB1#9`（−0.5868）。
- **结论**：取"不看 net" = **标准严格、接受参照有 4 例既存重叠**，与 §3.6 原则一致。

### 3.2 硬重叠 B：pad ↔ via

```text
同层 ∧ AABB 相交(gap<0) ∧ 双方 netcode≠0 ∧ netcode 不相等
```

**为什么两个 net 条件都必需**

| 去掉哪个 | 参照结果 |
|---|---|
| 去掉"双方 netcode≠0" | **140 例**（净增 **+123**）：全是"无 net 焊盘被有 net 过孔压"（身份 = **散热过孔阵列**：travellium `Q1/Q2#8` 47/42 个过孔压同一块 4.0×3.6 功率盘、iamdt `U5#8` 16 个、wzh `Q1#5` 3 个） |
| 去掉"netcode 不相等" | **965 例**（净增 **+948**）：同 net 的 in-pad via（刻意换层/散热）全变违规 |
| 两个都去掉 | **1088 例** |

（probe77 实测：无过滤 1088 ／ 仅双方 net≠0 965 ／ 仅不相等 140 ／ **正式 36**）

**why via 端不额外加条件**：无 net 的 via 只有 24 个，与 pad 的 AABB 重叠 **0 例** ⇒ 加与不加等价。
**参照结果：36 例**（转换角几何）= esp32s3r8n8 **20**（`U3` 19 例 17 个 pad + `L4` 1）+ gd32vw553 **8**（`U1` 的 `#5/#6/#15/#16/#25/#26/#35/#36`，全部压 GND）+ Mini控制板 **8**（`SW1` 7 + `U14` 1）；MiniMos **0**（旧版曾误记为 MiniMos，实为 Mini控制板）。
⇒ 这些是"**非正交件归一化后焊盘落到固定过孔上**"的真实重叠（旧口径 17 例多为 AABB 假阳性，见 §1.2）。

### 3.3 硬重叠 C：pad ↔ 禁布区

```text
同层（开槽视作 F/B 两层通用）∧ AABB 相交(gap<0) ∧ 排除禁布区项所属 footprint 自己的 pad
```

**为什么必须排除"所属 footprint"**：45 个开槽都是某个元件自带的（USB1 的 USB 口、SW1 的定位柱孔），开槽就长在它自己的焊盘旁边 ⇒ 不排除则每个带开槽的封装都自判违规（实测 2 例）。
**为什么阈值必须是"相交"而不是"留间距"**（probe77 实测）：

| 阈值 | 参照 |
|---|---|
| **相交（gap<0）** | **0 例**（不排除自家时 2 例） |
| `0≤gap<0.2mm` | 0 例 |
| `0.2≤gap<0.5mm` | **4 例**（最紧 0.364mm = fei `R45#2` × `USB1` 的开槽） |
| `0.5≤gap<1mm` | 13 例 |

⇒ 取"相交"是与参照完全一致的最保守选择。
**参照结果：4 例** —— lyg0927 `U1#18/#19` × `RST0` 开槽（−0.248/−0.213）、`U1#42/#43` × `BOOT0` 开槽（−0.033），均因该 `U1`（原始角 −45° → 270°）焊盘移动所致；`TT马达` hull 0 冲突。

### 3.4 软间距 S1 / S2 / S3

```text
S1 pad↔pad  ：跨封装 ∧ 同层 ∧ 不看 net ∧ 0≤gap<0.2
S2 pad↔via  ：同层 ∧ 双方 netcode≠0 ∧ netcode 不相等 ∧ 0≤gap<0.2
S3 pad↔禁布区 ：同层（开槽两层通用）∧ 排除所属 footprint ∧ 0≤gap<0.2
```

**角色：硬约束**（不是 reward 罚分）。**阈值：严格 0.2mm**，来源 = `.kicad_pro` 的 netclass `Default.clearance = 0.2mm`（原生 DRC 用的就是它，且只在异 net 之间要求）；**不做存量豁免、不降到 0.12**（理由见 §3.6）。

| 块 | 名义 | 身份 |
|---|---|---|
| S1 | **5** | fei 的两个「短接点0402」相邻 **0.0715mm**（设计意图：留可短接窄缝）+ esp32s3r8n8 3 例（`C54#2×L6#1` 0.030、`C34#2×U3#1/#2` 0.002） |
| S2 | **133** | 原板既存的"过孔贴异网焊盘"状态（EasyEDA 原板没按 KiCad 规则跑过 DRC） |
| S3 | **0** | 干净（曾看到的"USB1 距自家开槽 0.173mm"是**同封装**关系） |

**S3 阈值说明**：原生"铜到板边/开槽"标准其实是 **0.5mm**（`min_copper_edge_clearance`）；本项目为统一口径取 **0.2mm**（参照 0 例）。若将来忠于原生改 0.5，参照会新增 **4 例**（最紧 0.364mm = fei `R45#2` × `USB1` 的槽；另 3 例 = lyg0927 `U1#11/#35/#38`）。
**不纳入 `via ↔ via` 软间距**：纳入后参照有 **54 例恒定越界**（via 是固定对象 ⇒ 每个状态都违规）；且同 net 密排过孔阵列是常规做法。

### 3.5 出界

```text
footprint 的 pad ↔ 板框（AABB 越出即违规，不管 net）
```

| 口径 | 参照越界 |
|---|---|
| **全部 pad（本项目采用）** | **160 个 pad**（按层实例 320） |
| 只判 `net≠0` | 73 个 pad |
| 豁免"贴边件" | 0 个 |

**为什么"不管 net"**：出界是**纯几何约束**，与电气属性无关；只判 `net≠0` 时半孔排针里带 net 的那部分 pad 仍越界（73 例），规则不完整。

**5 个跨板边件（"结构性跨板边"，不是略微超边）** —— 口径：出界面积 = Σ(越界 pad AABB 落在板框外的部分面积)；占比 = 出界面积 ÷ 该 footprint 全部 pad 的 AABB 总面积。

| 板 | 件 | 封装 | pad / 越界 | 出界面积 | 占比 | 最大出界深度 | 越界中 `net≠0` |
|---|---|---|---|---|---|---|---|
| coloreasypico2 | `J1` | 半孔-孔-20P-2.54-1.27-无丝印 | 40 / **40** | 83.9mm² | **59.1%** | **2.178mm** | 20 |
| esp32s3r8n8 | `J2` | 半孔-孔-20**p**（小写） | 60 / 40 | 38.6mm² | 29.3% | 0.633mm | 20 |
| gd32vw553 | `J3` | 同上（小写 p） | 60 / 40 | 77.4mm² | 58.8% | 1.270mm | 11 |
| **合计** | **5 件 / 3 板** | | 240 / **160** | **242.2mm²** | **41.3%** | — | **73** |

- **锚点全部落在板框边线上**（`coloreasypico2 J1` 的 y=120.00 = 板下边 …）⇒ 位置本来就由板边决定（半孔 castellated 工艺形态）。
- **⚠️ 封装名有大小写变体**（`…-20P-…` vs `…-20p-…`）⇒ 任何按封装名匹配**必须忽略大小写**。
- **它们在板内仍有合法位置**（整件缩进板内即可）⇒ episode 仍可完成；严格口径的后果只是"**参考布局在这 5 个件上不合法**"（→ §0.6 未决 a）。

### 3.6 标准设计原则（Owner 拍案 2026-09-16）

> **人工参照布局本身不完美、也会犯错。**
> ⇒ 设计违规标准时，**首要保证标准自身的严格与正确，不为迁就参照布局而放宽**。
> ⇒ 连带：**"参照自检"不是门槛，只是诊断信息**；**"满分/完成" = 全部元件放置完毕 ∧ 无任何违规**，而不是"达到人工布局的 reward"。

| 决策 | 若为迁就参照会怎么做（已否决） |
|---|---|
| 软间距严格 0.2（参照 S2 越界 133） | 降到 0.12（参照 0）／全局"存量豁免" |
| 出界严格、不豁免（参照 160 pad） | 豁免 5 个"贴边件" ⇒ 参照 0 |
| 不做白名单 | 静态登记既存违规并跳过 |
| 硬重叠 A 不看 net | 要求"双方 net≠0"（少 1 例假阳性，但放行同 net 堆叠漏洞） |

**两个已知代价（记录在案）**：① **专家轨迹在违规点上不可复现** —— 出界 5 件（3 板）+ 软间距 S2 涉及的多块板，其"参考位置"本身违反标准；**但 episode 仍可完成**（agent 放到合法位置即可）。② **"满分/完成"的定义要按上式重述**（相关指标基准随之调整）。

### 4.2 六条硬要求

1. **所有 AABB / 与层相关的量一律带层信息**（footprint 按面；PTH 焊盘两面各计；开槽视作两层通用）。
2. **坐标与公式显式声明**：**转换数据用 mm 浮点**（raw 层是整数 nm）+ KiCad 板坐标（**Y 向下**）+ `板坐标 = 锚点 + R(−θ)·局部`；角度：原始 = 度、转换 = `{0,1,2,3}`；**精度下限 = 1 nm（1e-6 mm）**（§1.10）。
3. **唯一事实来源**：训练侧只允许读"转换数据"；原始数据只在测试/审查路径访问（`raw_*` 命名 + 只读）。
4. **转换数据同时保留"局部形式"**（以锚点为原点、未施加 θ）：agent 改 θ 后可直接用公式重算，无需回读原始数据或 pcbnew。
5. **pad 记录 + footprint 位置 ⇒ 能唯一反解每个 pad 的板坐标**；`pad 位置 = 焊盘中心`，**可视化/碰撞判定用 pad 的 AABB 框**（AABB 是派生量）。
6. **几何一律按「当前局面」反解，禁止读导入快照**（2026-09-18 新增；Owner："不能拿原始 footprint 位置算，那是**专家数据的**"）：
   `Pad.aabb` / `Pad.center` / `Footprint.hull_aabb` / `KeepoutRegion.aabb` 都是**导入时的源位姿快照**（= 专家布局位置），只有"该件仍在源位姿"时才等于当前几何。
   ```text
   落子（真实放置）     ：pcb_model.place_at(fp, anchor, rot) → 位姿化副本；
                          此后 placed 集合里放的就是它（env 落子那一刻调一次，之后复用）
   自带开槽（口径 A）   ：pcb_model.state_keepouts(model, placed) → 直接传 keepouts=
                          （静态禁布区恒在场 + 仅【已放件】的槽按位姿；未放置件的槽不上板，§0.6 p）
                          pcb_model.state_keepouts(model, placed) —— **唯一入口**（口径 A）
                          （曾有 pose_updated_keepouts / state_keepouts_by_pose 两名，已于 2026-09-18 删除）
   ```

### 4.3 位置链路与旋转公式

```text
板坐标 = 锚点 + R(−θ)·局部     x' = x·cosθ + y·sinθ ， y' = −x·sinθ + y·cosθ   （KiCad Y 向下）
逆变换：局部 = R(+θ)·(板坐标 − 锚点)
```

- 反解入口：`Footprint.hull_aabb_at()` / `pad_aabb_at()` / `pad_center_at()`（**θ=0 的局部几何是唯一依据**）。
- **"当前局面"反解（落子后必须用，§4.2-6）**：`pcb_model.place_at(fp, anchor, rot)`（pad/hull 的 aabb + center 实时反解）、`pcb_model.state_keepouts(model, placed)`（**禁布区唯一入口**，口径 A：自带开槽跟随已放件）、`board_to_local_aabb` / `keepout_at`（局部↔板坐标，几何原语）。
- 实测：hull 顶点与 pad 位置**最大误差 0.0000mm**（误用 `R(+θ)` 时误差 1.4~24mm）。
- 角度决策与"非正交件归一化"的后果见 §1.2。

## 5. 局面建模（状态）

> 状态 = **输入**。本节是 2026-09-16/17 重构的核心成果，落地在 `env/grid_render.py`。

### 5.1 为什么是 m×n 固定矩阵

决策链（每一步都有实测依据）：

1. 跨板训练/推理 ⇒ **维度必须统一**（否则网络输入形状随板变）。
2. 空间量的参照系选**板框坐标**（不用"元件中心相对坐标系"——**待放件还没有位置，无法以它为原点**；只有"评分某个候选"时才谈得上"从候选点看世界"，那是 per-candidate 的 ego 窗口，不是主状态）。
3. 但**对象级集合的宽度不统一**（每板件数 **10~97**）⇒ 回到 **m×n 固定矩阵**。
4. 板框形态实测（probe94/95/96）：**矩形填充率 ≥ 0.996** ⇒ 板框可用"参数化矩形 + AABB"表达，不需要多边形栅格化。

### 5.2 维度定案 `200×200×8` 与映射

**① 关键岔路：恒定"每格物理尺寸" vs 恒定"画布占比"**

| 方案 | 后果 |
|---|---|
| **板框缩放映射（Owner 拍案：200×200×8）** | 不同板的 `mm/cell` 不同（0.076~0.755mm），但维度统一；宽高比不失真（按轴缩放 ⇒ cell 非方形） |
| 恒定 mm/cell（早期"320×320 @0.5mm"方案） | 大板装不下，需要按最大板定画布 ⇒ 画布随板尺寸漂移 |
| 等比缩放（`uniform`，备选未采用） | cell 恒方形 ⇒ 旋转 = 转置自洽，但留空多、维度还是要按最大板定 |

**八张表 = 4 旋转 × 2 矩阵（L、G）**。

**② `r`（cell 尺寸）的夹逼依据**

| 约束 | 实测 | 结论 |
|---|---|---|
| **可见性**（最小件要占 ≥2 格） | 857 件：短边 min **0.81mm**、中位 1.68；**<0.5mm 共 0 件、<1.6mm 占 41.7%**（probe101） | r ≤ 0.6 才让最小件 ≥2 格 |
| **位置预算**（每元件可用合法格数） | probe100：r=0.5 → 最紧板 47.4 格/件；**悬崖在 1.0~1.5mm**（1.5 时 HPWL 损失跳 35×） | r ≤ 0.8 |
| **目标损失**（格点量化） | probe99：r=0.5 → HPWL 中位损失 **−0.16%**（可忽略，符号有正负） | r ≤ 1.0 |

⇒ 三条交集 ⇒ **理想区 r = 0.5~0.6**（"所有件都舒适"的区间，**不是硬门槛**）。
**实际选型 200×200（`fill` 铺满）**覆盖最大板 151mm ⇒ **长轴 cell = 0.755mm（已超出理想区）、短轴 0.421mm**：
超区的唯一代价是**极小件的可见性** —— 全数据集 **<1 格 0 件、<2 格 7 件**（约 0.8% 的件）；
**最紧的是 165W 板**（最小件短边 1.47mm = **1.95 格**，差 0.05 格到 2 格，接受）；
**100×100 不可行**（同板最小件 0.98 格，7 件不足 1 格）。

**③ 两个必须记住的性质**

- **4 张旋转表各自独立存放**（**表从不合并**）；所谓"共用标尺"只发生在**归一化统计量**（p5/p95 在 4 个旋转的**同一个样本池**上取一次）——见 §5.4。
- **`fill` 映射下 cell 非方形 ⇒ 4 张表之间没有"转置"关系**（网络不能依赖该对称先验）；`uniform` 才有（备选未采用）。

### 5.3 L（合法位置矩阵）

```text
L[k][i][j] = 把待放件放到【格中心 (i,j)】、旋转 k 时，是否**不违规**（True = 合法）
形状 (4, 200, 200) bool ｜ 判定对象/口径 = §0.3（三类违规的并集）
```

**① 关键简化：硬重叠 ∪ 软间距 = `gap < 0.2`** ⇒ **每个 (pad, 障碍) 对只需戳 1 个矩形**（不是 2 个）。前提是三类对象的硬/软**过滤条件一致**（§3.1~3.4 逐条核对），且阈值可配：判据写成"对象对 → 阈值 + 过滤函数"的表，**默认三类阈值同为 0.2 才合并**，一旦不同（如 keepout 改回原生 0.5）自动退化为 2 个矩形。

**② 四类禁区**（全部在**锚点空间**算矩形）

| 禁区 | 做法 |
|---|---|
| **出界** | 所有 pad 的允许锚点区间**求交** ⇒ **恰好 1 个矩形** |
| **pad↔pad** | 同层、**不看 net**、不同 footprint（当前件未放置 ⇒ 天然成立） |
| **pad↔via** | 同层 ∧ **双方 netcode≠0 ∧ 不相等**（pad 无 net 时 via 完全不是障碍；去 net 过滤会把 36 例变成 1088 例，§3.2） |
| **pad↔keepout** | 同层 ∧ 排除 `owner_ref == 本件` |

三类障碍**按层分桶**（`pad_obs[lay] / via_obs[lay] / keep_by_layer[lay]`），逐 pad 用它的记录层取桶（§1.4）。

**③ `_EPS = 1e-9`（**单位是 mm**，即 1e-3 nm = 1 pm —— ⚠️ **不是 1nm**；它兜的是"浮点末位差"而非 nm 量化平局，故与 §1.10 的 1nm 精度下限**不冲突**，两者是不同性质的事）保守容差（2026-09-17 加入）**：禁区向外扩、板框允许区向内收 ⇒ **任何 `Judge` 判违规的位置必然被 `L` 判禁**（**危险方向结构性恒 0**，不再靠浮点运气）；代价仅是"平局格"被保守禁掉（实测 6 板共 **29 格 / 240,000 = 0.012%**：wzh 24 格是**板框边缘平局**、coloreasypico 5 格是**阈值平局 `gap=0.2`**）。

**④ 禁布区阈值 = 0.2mm（Owner 2026-09-17 拍案）**：三类对象硬/软阈值全 0.2 ⇒ 合并式成立（§3.3/§3.4 的 0.5mm 原生口径不采用）。

**⑤ 实现：解析式矩形 stamping（"减法"思想 + 差分数组）**

核心思想：**不逐格问"这一格合法吗"，而是把"被禁止的锚点区域"作为一批矩形算出来，再从"板内允许区"里减掉。**

```text
L[k] = inb ∩ ¬forbidden                       ← 减法：合法 = 板内 − 禁区
  inb       ：板内允许区（所有 pad 的允许锚点区间【求交】⇒ **恰好 1 个矩形**）
  forbidden ：所有禁区的并集（每个 (pad, 同层障碍) 对 ⇒ **恰好 1 个矩形**）
```

**步骤 1：把"障碍 + pad"变成"禁止锚点矩形"（滑动 / Minkowski 式）**

对一对 `(pad：半尺寸 (hx,hy)、中心相对锚点偏移 (cx,cy))` × `障碍 AABB B`：锚点落在哪儿才让 pad 与 `B` 冲突？把 pad 沿 `B` 滑动，锚点的禁止区恰好是

```text
① 障碍 ⊕ pad 半尺寸      g = [B.x1 − hx, B.y1 − hy, B.x2 + hx, B.y2 + hy]
② 再加 0.2 软间距环       g ← g ∓ (soft + _EPS)            （软间距并入，见 ①）
③ 倒推回【锚点空间】       [lo_x, hi_x] = [g.x1 − cx, g.x2 − cx]（y 同理）
```

⇒ **一个 (pad, 障碍) 对 = 一个矩形，与"障碍多大"无关** —— 这是全部效率的来源。

**步骤 2：mm 区间 → 格索引区间（两种区间语义，别混）**

```python
_idx_open  (v_lo, v_hi, …)   # 严格 v_lo < center < v_hi  ⇒ 用于「gap < soft」（开区间：相切(gap=0)不算）
_idx_closed(v_lo, v_hi, …)   #      v_lo ≤ center ≤ v_hi  ⇒ 用于「板内」（闭区间：贴边算在内）
# 共同换算：i = floor((x − x0)/cell)，center(i) = x0 + (i+0.5)·cell
#   ⇒ u = (v − x0)/cell − 0.5，再取 floor/ceil，最后 clip 到 [0, m−1]（越界部分自动裁掉）
```

**步骤 3：差分数组（"加法代替逐格填充"）**

```python
diff = zeros((m+1, m+1))                      # 多一行一列，供 i1+1 / j1+1 落脚
_add_rects(diff, i0, i1, j0, j1, m):
    np.add.at(diff, (i0,     j0    ), +1)     # 只在【4 个角】做 ±1
    np.add.at(diff, (i1 + 1, j0    ), -1)
    np.add.at(diff, (i0,     j1 + 1), -1)
    np.add.at(diff, (i1 + 1, j1 + 1), +1)
forbidden = diff.cumsum(0).cumsum(1)[:m, :m] > 0     # 一次二维前缀和 ⇒ 每格"被几个矩形覆盖"
```

- 复杂度从 **O(Σ 矩形面积)** 降到 **O(#矩形) + O(m²)**（一次前缀和）——这就是"不逐格"的关键；
- 必须用 `np.add.at`（**无缓冲**加法）而不是 `diff[i0, j0] += 1`：同一角点可能被多个矩形同时命中，花式索引的 `+=` 会互相覆盖。

**步骤 4：层匹配 = "选桶"，不是逐对比较**

`_obstacles()` 把三类障碍**按层分桶** `{(0,): … , (1,): … , (0,1): …}`；逐 pad 用它的**记录层集合**直接取对应桶（§1.4）⇒ 同层判定在"取哪一批矩形"时就完成了。net 过滤同理在 pad 层做（如 pad↔via 要求双方 `netcode≠0` 且不相等，用 mask 过滤后再 stamp）。

**步骤 5：出界单独求交（也只有 1 个矩形）**

```text
每个 pad：锚点须落在 [va.x1 + hx − cx, va.x2 − hx − cx] × [va.y1 + hy − cy, va.y2 − hy − cy]
⇒ 对所有 pad【求交】得 inb（`_idx_closed` + 向内收 `_EPS`，见 ③）
```

**步骤 6：拼装**

```python
out[k] = inb & ~forbidden        # 板内 且 不被任何禁区覆盖 = 合法
```

**成本（实测）**

| 项 | 值 |
|---|---|
| 主体 | 每步矩形数 = `\|当前件 pad\| × \|同层且过 net 过滤的 via\|`（大板可达 **10⁴~10⁵** 个矩形；**§3.2 的 1088 是"全板无 net 过滤的违规配对数"，不是每步矩形数**） |
| 前缀和 | 4 × (201×201) 累加，一次、向量化 |
| **总计** | **4.7 ~ 15.2 ms/步**（最大板 300W 15.2ms） |
| 对照（逐格调 `Judge`） | 4×200×200 = 16 万次判定/步 ⇒ **29 ~ 232 s/步**（**差约 10⁴ 倍，不可行**） |

**⑥ 验收（两条路径必须同源）**：抽样（均匀 + **边界格**，2000 格/组）+ **6 场景全量穷举**（**40,000 格 × 4 旋转 = 160,000 个 `(k,i,j)` 候选**，双向对拍）⇒ **危险方向 0 偏差**；"过度封锁"必须能用"阈值平局 / 板框边缘平局"解释（见 §3.8）。
**＋第三方独立验收（probe151，2026-09-17，Owner 要求"再不放心一次"）**：先用 **KiCad 本体**当外部权威对拍几何（pcbnew 自己把 footprint 摆到 4 个转换角，6 板 2814 个 pad 点）⇒ `max|AABB 差| = max|中心差| = **5.7e-14 mm**`；再用**独立实现**（暴力栅格化，不用差分数组、不用 `_idx_open/_idx_closed`）全量重算 6 场景 160,000 格 ⇒ **`danger = 0`**（L 从不放过违规）、`over = 64`（wzh 24 + coloreasypico 40）且**全部 `|余量| ≤ 1.7e-14 mm` = 浮点末位平局**（其中 18 格 `Judge` 也判 `soft.pad_via` 违规 ⇒ L 只是"更早禁掉"，安全方向）。
**＋旋转专项（probe154/155，2026-09-17）**：⚠️ 上述 6 个场景的板**都不含 45°/135° 非正交件** ⇒ 那条"归一化"路径需单独验收。结果：① 18 板实测共 **16 个非正交件**（3 块板：climbsnail / 另一块 li-chuang / lyg0927；含唯一非等距 `X1 = −0.62°`）；② tie 规则与 §1.2 一致（+45→0、−45→270、+135→90、−135→180、−0.62→0）；③ **归一化让焊盘最多移动 3.87mm**（lyg0927 `U1`；SW1 3.10、U3 3.28、U14 2.56）⇒ 这就是"旋转真正改变几何"的量级；④ 我们的反解在 **16 件 × 4 个转换角** vs KiCad 本体 `max = 4.0e-14 mm`；⑤ 在"**待放件本身是非正交件**"的 5 个有效局面上独立验收：`danger = 0`、`over ≤ 2`（`｜余量｜ = 2.8e-15 mm` = 平局）、`max|ΔHPWL| ≤ 1.5e-5 mm`、`max|Δσ| ≤ 1.9e-12 mm`。

### 5.4 G（增益矩阵）

```text
G[k][i][j] = 0.7·z_hpwl + 0.3·z_disp     合法格 ∈ [0,1]
           = −inf                        非法格（= L 的补集）
形状 (4, 200, 200) float32
```

**① 两个分量（原始量，均 ÷ 板对角线 `D_board = sqrt(W²+H²)`）**

| 分量 | 公式 | 口径 |
|---|---|---|
| HPWL 增益 | `s_hpwl = (−ΔHPWL)/D_board` | **排除电源/GND**（§2.5）、连接点 = pad 中心、**不分层**、未放置件不计；`ΔHPWL ≥ 0` ⇒ 越大（越接近 0）越好；含"自 net 内部跨度"常量项（该件在某 net 上 ≥2 pad 而该 net 尚无已放 pad） |
| 跨 net 离散度增量 | `s_disp = (σ_after − σ_before)/D_board` | `σ` = **各非电源 net 的 bbox 中心的标准差**；参与 net = "**放上当前件之后**该 net ≥2 个点"（含"1 个已放 + 本件 1 个"）；**越大越好**（net 中心彼此越分开） |

> ⚠️ **取点必须用"当前位姿"（2026-09-18 修复）**：两个分量的**已放件连接点**来自 `net.pads[].center`
> ——那是**导入时的源位姿快照（= 专家布局位置）**。策略落子后必须映射到 `place_at` 生成的位姿化对象
> （`grid_render._pose_pad_index` / `_center_now` 按下标映射；`place_at` 保序）。
> 实测（verysunshine 挪一个"持有 net 极值点"的已放件 5mm）：位姿化后与独立重算差 **3.8e-6 mm**，
> 而用源快照差 **9.06 mm**；`PcbModel.hpwl` 位姿化 212.96 vs 源快照 **190.25**（差 22.7mm）。
> 另注：**HPWL/ΔHPWL 只对"极值点"的移动敏感**（挪内部件不改变 net 包围盒；且 `ΔHPWL` 还要求该 net 被待放件占用）。

**② 归一化三步（缺一不可）**

```text
① 内部（跨板）：两者都 ÷ D_board          （20 板对角线 21~173mm 差 8 倍）
② 步内（同一步）：**4 张表全部算完后共用一把标尺** —— 把 4 个旋转的合法格投进**同一个样本池**去估 p5/p95
                  （**表从不合并**：4 张 L / 4 张 G 独立存在，动作与检索都按 4 组走；"共用"只在这两个分位数上），对每个分量**各取一次 p5/p95**
                  z = clip((s − p5)/(p95 − p5), 0, 1)      ← 稳健 min-max
③ 结合：G = 0.7·z_hpwl + 0.3·z_disp ∈ [0,1]
```

- **为什么必须归一化**：`s_hpwl` 跨度 **1.297** vs `s_disp` 跨度 **0.0147**（**88×**）；不归一化时离散度对 G 的影响上限仅 `0.3×0.0147 = 0.0044`（HPWL 项是 0.908）⇒ **λ 形同虚设**。归一化后两者才各占满 0.7/0.3。
- **为什么"共用一把尺"（而不是逐旋转各自归一化）**：逐旋转各自 min-max 会把**每张表的最优都拉成 1.0** ⇒ 跨旋转不可比。实测证据：各旋转 max G = bliysfyt `[0.743, 0.238, 0.475, 0.894]`、jackt `[0.939, 0.961, 0.929, 0.830]`（**4 个旋转都没触顶**）。
- **两趟式，禁止逐旋转归一化**（实现层保证：`gain_maps` 一次调用**必须**返回 4 张表）。
- **分位取 p5/p95**：p1/p99 在本数据上差别很小（下尾极短）；真正决定分辨率的是**下端点**（若要给"好区域"更多分辨率，可改 `p50–p99`，代价是 z=0 语义变成"中位及以下"）。
- **已否决**：softmax 归一化（实测输出量级 ~1/N、自然温度下近乎均匀、池耦合、β 仍是量纲常数）。

**③ 退化守卫（防止 0/0）**

```text
某分量在池内恒定（p95 − p5 < 1e-12）⇒ 该分量给常数 0.5（"中立票"，不改变排序）
两分量【同时】退化 ⇒ G ≡ 0.5 全场 + 返回 degenerate=True
```

- **何时发生**：该件涉及的**每条 net（含电源）**都还没有已放 pad 且它自己不成网（"net 冷启动"）⇒ ΔHPWL ≡ 0 且 Δσ ≡ 0。实测这类 **G 退化步（口径 A：全 net 冷启动）占 23.6%**（P1，857 步）—— **且该比例只取决于放置顺序与 net 归属，与 L 精度无关**。
- ⚠️ **两个口径别混**：§6.2 的"迷茫步"是**口径 B（只看非电源 net 全冷，电源专属件另用"共享电源网数"兜底）**，数值 **13.0% → 7.3%**；口径 A（23.6%，含电源网冷启动）与口径 B **统计总体不同、两数不可直接比较**。另注：§7.2 的"目标零贡献件 **201 件 = 23.5%**"是**第三个指标**（该件对 HPWL/离散度零贡献的件数占比），与 23.6% 无关，勿混。
- **`degenerate` 只作元数据**：**不进 G 张量、不进网络输入**；供 env / 检索 / BC 跳过（这 23.6% 的步里 G 无信息，位置只能靠占用/空间先验）。
- 空合法集（死锁）时：`G` 全 −inf、`degenerate=True`；**env 行为（Owner 2026-09-17 拍案）：立即终止 episode，并记录"放置完成度"**（= 已放件数 / 总件数；指标精确定义见 §0.6 未决 m）。奖励侧是否加"终局罚分 / 进度奖"**尚未定稿**（候选与定标常数见 §7.3）——**终止行为与奖励是两件事：前者已定、后者未定**。

**④ 实现与验收**

```text
hpwl_gain_maps(...)   → −ΔHPWL（原始，含旋转相关的常量项）
dispersion_delta(...) → Δσ（只对"被本件触及"的 net 逐格算中心 ⇒ O(触及net×格数)）
gain_maps(...)        → (G, degenerate)   ← 组合层：两趟式 + 共用标尺 + 退化守卫
```

- 验收：σ 自校验（直接构造 vs 增量算法，差 ~1e-13）｜ HPWL 端到端 vs 独立重算（18 个采样点，最大 **3.3 nm**）｜ G 的有限域**严格等于 L**、合法格 ∈[0,1]、非法格 −inf ｜ **专家格 G 金表**（6 场景）｜ 共用标尺可证（§5.4②）。
- **＋第三方独立验收（probe151）**：6 场景 × ~2400 采样格（含 4 旋转 H/σ 极值格与专家格）按定义直接重算 ⇒ `max|ΔHPWL| = 7.6e-6 mm`（= **float32 存储精度**，相对 7.6e-8）、`max|Δσ| = 3.9e-12 mm`、组合层 `max|ΔG| = 3.0e-8`；专家格 G 与金表一致（差 ≤ 3e-4）；`G` 的有限域 = L、∈[0,1]、非法格 −inf、各旋转 max G 不全为 1.0（共用一把尺）全部复核通过。
- **＋旋转专项（probe155）**：6 场景的板不含非正交件 ⇒ 另在"**待放件本身是非正交件**"的 5 个有效局面上复验（`U14 −135°→180°`、`SW1 +45°→0°`、`U1 −135°→180°`、`X1 −0.62°→0°`、`U1 −45°→270°`）⇒ `danger = 0`、`over ≤ 2`（`｜余量｜ = 2.8e-15 mm`）、`max|ΔHPWL| ≤ 1.5e-5 mm`、`max|Δσ| ≤ 1.9e-12 mm`。
- 成本：G **2.6~24.4 ms/步**（最大规模板 coloreasypico 合法格 39,740 时 6.2ms；lr1388 因 net 多最贵 24.4ms）。

### 5.6 层与状态

- **L、G 都只需一套（4 张旋转表），不按层拆**：① 动作空间已取消换层（§1.4）⇒"在哪层"是**数据事实**；② L 的层过滤在**内部**完成（逐 pad 按记录层取障碍桶）；③ G **刻意不分层**（§0.3 的纯二维口径）。
- **分层会改变 G 的口径**：probe121 实测（**is_power 修补后重跑**）**699 条非电源 net 里 43.8% 跨层**，分层会让 **41.3% 的 net 中心**变化（F/B 中心分离 >1mm 的占 40.6%）⇒ HPWL（一个矩形）与离散度（两个中心）会"互相打架"，因此定案"都不分层"。
- **4 张表之间没有转置关系**（`fill` 映射下 cell 非方形，§5.2③）。

### 5.7 精度分工（三层，务必分清）

| 环节 | 表示 | 精度 | 说明 |
|---|---|---|---|
| **状态输入** | cell 栅格 | 0.5mm 级（粗） | 只是摘要，学"往哪个区域放" |
| **动作/掩码索引** | cell 栅格 | 离散 | cell 是动作编号；mask 是同一条 lattice 上的 bool |
| **违规判定** | **连续 mm** | **1nm** | 锚点 mm → pad AABB mm → `Judge` 算 gap；via/keepout/板框全是原始精确 AABB |
| **执行复核** | 连续 mm | 1nm | 选中 cell 后取**格中心 mm**，再过 `Judge.judge()` 精确校验 |

- **唯一误差来源 = 动作离散化**（锚点只能落在格点上）：实测 HPWL 中位损失 **−0.16%**（probe99），且**只影响最优性、不影响正确性**（非法候选被 mask 掉，永不执行）。
- **可选的正解**是"cell 内解析精调"（单件 HPWL 对位置分段线性 ⇒ 最优位置集是一个盒，把锚点 clamp 进盒即可）——**暂不采纳**（§0.6 未决 h）。
- **栅格分辨率与判定精度完全解耦**：哪怕降到 64×64，判定依旧精确到 1nm，只是可选位置更稀疏、元件更看不清。

### 5.8 P / 占用矩阵的定位（曾考虑、已定论）

- **初衷**：用 P（记录已放件所占格）把 L 的计算域从 200×200 缩小到"障碍附近"。
- **结论：不需要** —— L 的解析 stamping 已是毫秒级（§5.3⑤）；真正的大头是 `(pad × 同层障碍)` 对，而障碍都在板上、都在"脏区"里 ⇒ 裁剪域省不下什么。**不逐格遍历**才是关键（逐格 Judge 是 29~232 秒/步）。
- **P 的定位（留作共享结构，不进状态）**：① 占用/空间压力（可作为可视化/诊断）② 死锁快速检测（合法域空 / P 充满）③ 检索键的一部分 ④ 调试可视化。
- **红线（若将来真要用 P 裁域）**：P 必须覆盖**所有**障碍类型（**已放件 + via + keepout，缺一不可**，否则会漏禁 ⇒ 直接产生违规动作），且**域内仍必须用精确几何**（P 只能当裁剪器，不能当障碍本身）。

## 6. 动作与顺序

> 动作 = **输出**。本节 = 动作空间定义 + 固定放置顺序（2026-09-17 拍案）。

### 6.1 动作定义

```text
每步动作 = (旋转 k ∈ {0,1,2,3}, cell (i, j))          —— 共 4×200×200 = 160,000 个候选
不含"选件"（放置顺序固定，§6.2）｜ 不含"换层"（件只在原本的层活动，§1.4）
合法动作 = L[k][i][j] == True（非法格在 G 上为 −inf，在策略上被 mask）
```

- **执行**：选中 (k,i,j) ⇒ 取**格中心 mm** 作为锚点 ⇒ 过 `Judge.judge()` 精确复核（理论必过，§5.3③ 的 `_EPS` 保证）⇒ 落子，并以"已放件"身份参与后续 L/G 计算。
- **动作规模与备选**：160,000/步（其中约 8,700 合法格，见 §5.2 与附录 A probe112/127：lr1388 为 8758 格）。**备选（未采用）**：候选点式（从 L 采样 K 个候选，动作头压到 `4K`，允许非格点位置）——若将来要"零量化损失"再升级，状态与判定都不变。
- **与顺序的关系**：固定顺序 ⇒ 每步的"待放件"由顺序决定，网络**不需要**做"选件"决策。

### 6.2 固定放置顺序（Owner 2026-09-17 拍案：动态 + 0.7 : 0.3）

**① 为什么需要换掉旧规则（纯面积降序）**

| 指标（20 板） | 旧规则（纯面积降序） | 新规则 |
|---|---|---|
| **迷茫步占比**（该件的非电源 net 全冷 ⇒ G 退化） | **13.0%** | **7.3%** |
| **首→次 pad 步距**（一条 net 第 1→第 2 个 pad 相隔步数 = credit assignment 延迟） | **7.8 步** | **3.85 步** |
| 前 25% 步已放面积（"大件先放"强度） | 79.1% | 76.9% |
| 前 10% 大件平均步位置 | 0.026 | 0.041 |
| 电源专属件平均步位置 | 0.517 | **0.383** |

**② 规则定义**

```text
score_t(r) = w·a_norm(r) + (1 − w)·c_norm_t(r)          w = 0.7（面积权重；连通性权重 0.3）
  a_norm    = log1p(hull 面积) 在【全部件】上 min-max 到 [0,1]      （静态，整局只算一次）
  c_t(r)    = |非电源 nets(r) ∩ warm_t|
              warm_t = 已放件涉及的非电源 net 集合                 （**每步增长**）
  c_norm_t  = 把 {c_t(r)} 在【当步剩余候选】上 min-max
  电源专属件（非电源 net 为空，23.5%）：c 改用 |全部 nets(r) ∩ warm_all_t|（兜底）
  tie-break = 面积↓ → pad 数↓ → ref↑                                （**全序**）
```

- **权重语义（补偿比例）**：连通性拉满的候选最多能抹平 `(1−w)/w = 43%` 的面积差（w=0.8 → 25%、w=0.5 → 100%、w=0.2 → 400%）。这也解释了"w=0.7 仍能把迷茫压掉 44%"：面积仍主导，但**同档面积内**由连通性决定。
- **为什么连通性必须动态（每步重算）**：静态度量（net 条数 / 加权度）只能把迷茫压到 9.2~13.5%，**credit assignment 延迟压不下去**（静态最好 5.3~6.1 步 vs 动态 2.3~5.5 步）——因为静态分数不随局面变化，无法"沿着刚放完的件继续爬"。
- **为什么用"非电源 net"做连通性**：用全部 net（含电源）时迷茫只能到 9.9%（电源网把一切拉平）；用非电源 net 可到 7.3%。代价是"电源专属件"得分恒 0 ⇒ 用**电源网兜底**（否则它们被推到 0.77~0.87 位置）。
- **归一化必须在 log 上做 min-max**：面积中位 5.12mm² vs max 3184mm²（600×），线性 min-max 会把 99% 的件压成 ≈0。

**③ 四条实现契约**（写进 `env/order_plan.py` docstring）

1. **纯函数**：只依赖 netlist + 常量 ⇒ 与元件位置、源布局、策略**全部无关**。
2. **可离线预计算并冻结** ⇒ **训练时零成本**（顺序与位置无关，产物是一张固定列表）。
3. **确定性**：tie-break 必须**全序且以 `ref` 收尾** —— Python 的 str 哈希随机化（`PYTHONHASHSEED`）会让 `set/dict` 迭代顺序跨进程不同，key 不到 ref 级别时结果可能漂移。实测：打乱元件输入顺序 5 次，20 板顺序**逐位一致**。
4. **与策略无关** ⇒ 不破坏"固定顺序"拍案：顺序只依赖"哪些件已放"，在固定顺序下恒等于**前缀**（专家库重放/检索键始终一致）。**反例警告**：若让顺序依赖**位置**，才会破坏一致性——本设计不做。

**④ 实现与测试**

```text
实现：env/order_plan.py —— plan_order(model, comps=None, w_area=0.7, power_fallback=True) -> list[str]
      （另含 area_scores() 与 order_metrics()：迷茫A / 首→次步距 / 前25%步面积 / 大件位置 / 电源件位置）
成本：整板 0.14~5.2 ms（97 件最大板 4.78ms）；20 板合计 37 ms
测试：tests/kicad/test_order_plan.py（41 项）
      A) 20 板顺序 SHA1 金表（含件数/首末件）
      B) 确定性自检（打乱输入顺序 5 次逐位一致）
      C) 聚合指标金表（fog 0.072684 / delay 3.85 / a25 0.769121 / big 0.041343 / pw 0.382520）+ 四条阈值
```

**⑤ 与"人类经验"的边界**：顺序只决定**时机**（什么时候放），**不决定位置**——"电源专属件是否贴在它服务的 IC 电源脚旁"属**未建模的人类经验**（§11），顺序规则把它们的**时机**拉回到其电源轨附近（0.383），但不保证**位置**正确。

### 6.3 mask 与候选生成

- **mask 的基础 = L**（§5.3）；两条独立路径（解析 stamping ↔ 逐点 `Judge`）必须**对拍 0 偏差**（§3.8）。**叠加单步预测掩膜后**：`action_mask = L & lookahead`（见下条，结果必 ⊆ L）。
- **两层校验**：训练/推理用 L（快）；执行前用 `Judge` 复核（准）；两者不一致即报错（这正是 `_EPS` 保守容差要解决的问题）。
- **单步预测掩膜（lookahead mask，2026-09-18 定口径并落地 `env/lookahead.py`）**：对当前件的每个候选动作，**假装真放下去**，看**固定顺序的下一个件**是否仍有合法格；没有 ⇒ 该动作被 mask（$mask \subseteq L$，比 `L` 更严格）。
  - **算法（Owner 定）**：先算一次 `L_next0`（没放当前件时的下一个件 L）；遍历候选时只需把"当前件新覆盖的禁区"从 `L_next0` 里**减掉**（`L_next(after) = L_next0 \ 新禁区`）——**不重算整张 L**（单调性：放件只增障碍）；只要能找到一个存活格就早停。
  - **实现**：利用**平移不变性**（冲突只取决于锚点差）预生成**紧凑整数位移表**（逐 `(k,kf)` 懒构建），再用**批量查表**判定；另有"被杀矩形并的外接框 + `L_next0` 前缀和"的 **O(1) 快路径**先放行绝大多数候选（这条在"空板/稀疏"大规模场景是主力）；查表分批控内存。
  - **边界（Owner 定）**：`L_next0` 全空 ⇒ **全部 pass（保留 `L` 不变）**——"下一个件当前就没位置"不是本候选的过错，照算会把动作空间清空；"已死"交给 env 终止（§5.4③）。
  - **实测成本/严格度**（`tests/kicad/test_lookahead_mask.py`；2026-09-18 复核实测：快档 **17 passed / 3 skipped（15.6s）**、重档 **20 passed（47s）**）：bliysfyt `L=274 ⇒ 保留 264（砍 10）`、**10 ms/步**；jackt `152 ⇒ 152（砍 0）`、**3 ms**；verysunshine `3317 ⇒ 3317`、**8 ms**；稀疏极端（空板）lr1388 `L=53763`、**15 ms**、bliysfyt `L=8113 ⇒ 保留 7264（砍 849 = 10.5%）`、**428 ms**（⚠️ 比修复符号前的 174 ms 慢 —— 因为"砍"变多 ⇒ 精确路径工作量上升，**不是性能回退**）。与**独立参照**（槽随件平移的正确版）逐候选对拍 **0 不一致**。
  - **⚠️ 2026-09-18 审计发现并修复一个真 bug（**危险方向**）**：精确路径的**位移表索引符号写反**（查表用 `now − next`，而模板/表的约定是 **`next − now`**）。后果：**模板不对称时漏杀** ⇒ 把"会堵死下一个件"的动作**保留**（误留）。**隐蔽性**：只在"候选落到精确路径 + 模板不对称"时出现；**稠密场面砍≈0（jackt/verysunshine 砍 0）⇒ 原来的抽样对拍完全看不见**；稀疏（空板）场面才暴露（bliysfyt 空板：修复前"砍 434"、修复后 **849（10.5%）** ⇒ 原来**少砍了 415 个**本该砍的动作）。修复：`dI/dJ` 改为 `cn − cells`，并把约定写进 `conflict_table` / `conflict_table_from` 的 docstring。**验收**：`test_conflict_table_matches_geometry`（**全枚举**位移表 vs 几何，58 万 + 9.6 万项 0 不一致）+ `test_mask_matches_recompute_sparse`（稀疏场面对"从零重算"双向对拍；重档**全查被砍候选** 849 个）+ 独立探针 probe179/180/182（7 局面 962 候选 + 保留侧 3000 抽样 ⇒ **误留 0 / 误杀 0**）。
  - **深度 = 1**（Owner 定）：实测 `depth=1/2/3` 掩膜**逐格相同**（触发者恒为下一个件），且**减深度几乎不省时间**（差 7%）⇒ 时间大头恒为"最紧件 × 候选数"。
  - **核心命题已验证（probe166~168，2026-09-18）**：`增量压缩 == 把件真放下后从零重算`，且 `掩膜保留 (k,i,j) ⟺ 真放下后 comp_next 仍有合法格` —— 4 板上 **逐格不一致 = 0**（`bliysfyt` / `jackt` / `verysunshine` 直接 0；`lr1388` 初测 152/160 不一致，深挖确认**与增量算法无关**：把两边**开槽集合口径对齐**后 **0/80**）。⇒ **增量算法正确**；差异 100% 来自"开槽口径 (A)/(B) 混用" ⇒ **已裁决为 (A) 并落地**（§0.6 p：唯一入口 `state_keepouts`）。
  - **剩余待办（非阻塞）**：① 紧度兜底（若后续件比下一个件更紧，可选纳入）② 被 mask 候选的成本 ∝ `|L_next0|`（正在优化的批量/相关路线，见附录 A probe156~163）
- **候选生成（仅当将来升级为候选点式）**：从合法区**均匀采样 + HPWL 引导采样**（同 net 已放 pad 附近加密）+ **永远保留源位置候选**，K 取 64~256。

## 7. 目标与奖励

### 7.1 HPWL 口径（Owner 拍案）

| 项 | 口径 |
|---|---|
| **定义** | 对每个 net 取其全部连接点，`(max_x − min_x) + (max_y − min_y)` |
| **连接点** | **pad 中心**（不再单独存 pin 表） |
| **电源网 / GND** | **排除**（判据见 §2.5/§7.2） |
| **分层 / 过孔** | **不分层、不考虑过孔信息**（纯二维）⇒ 不需要过孔代价参数 |
| **未放置元件** | **其 pad 不计入** ⇒ HPWL 在 episode 内**递增**（每放一个元件，其 pad 加入所属 net 的极值统计）；实现 = `PcbModel.hpwl(refs=已放置, poses={ref: 当前位姿})`（⚠️ 位姿 ≠ 源位姿时**必须传 `poses`**，否则取到导入快照；§4.2-6）|
| **不可动对象** | `TT马达`（零 pad）与禁布区**没有连接点 ⇒ 不进 HPWL**；独立焊盘（本数据集 0 例）若带 net 则按其 net 计入 |
| **与旧 reward 的区别** | 旧的 "net 聚合度"（各元件 AABB 中心到网中心的平均距离）**不是** HPWL；若改用 HPWL 作 shaping，权重要重新标定（→ §9 留空） |

### 7.2 电源网判定：判据、修补与依据

**判据（单点定义）**：见 §2.5（四级：白名单 → 排除使能/参考/检测类 → 前缀 → 电压名尾 / 轨子串）。
**为什么"排除电源网"**：HPWL 度量的是"跨板的**点到点连线**"；而电源/地靠**敷铜（铜皮）+ 短引线**实现，其"线长"**不由元件摆放决定**（铜皮覆盖由铺铜轮廓决定、短引线由"引脚到最近铜皮"决定）。用 HPWL 度量电源轨 = **用错了度量**。

**形态证据（probe140，逐 net 走线 + 敷铜实测，20 板）**

| 类 | net 条数 | 平均走线长 | 平均敷铜面积 | 有敷铜的 net 比例 |
|---|---|---|---|---|
| **信号** | 573 | **17.7 mm** | **5.2 mm²** | 52.7% |
| **电源（已判）** | 21 | **117.2 mm** | **7556.9 mm²** | **95.2%** |
| **被漏判的轨** | 9 | **144.5 mm** | **337.3 mm²** | **77.8%** |

细节：GND = 879 段走线 / 1092.3mm / 383 个 zone / 15.7 万 mm² 敷铜（**主体是平面**；"走线"平均每段 **1.24mm** = 引脚→铜皮的短引线 + 缝合过孔）；3V3 = 601 段 / 778.3mm / 254 zone（**混合形态**，平均每段 1.29mm）；P12V 917.8mm²、P60V 832.5mm² 几乎全是铜皮。⇒ 电源轨与信号在"走线/敷铜形态"上差 **1~3 个数量级**。

**2026-09-17 修补（Owner 拍案）**：旧判据只有"精确白名单 + 前缀"⇒ **漏判 10 条真轨 / 264 pad（= 非电源 pad 的 12.4%）**，其中 **`3V3` 挂 86 个元件 / 168 pad** 被算进 HPWL（会让目标被这条总线主导）。

### 7.3 奖励：候选、陷阱与现状（**尚未定稿**）

**候选形式**（当前讨论基线）：`r_t = −ΔHPWL_t / D_board`（每步即时回报）。

**⚠️ 陷阱：telescoping ⇒ 会诱导"故意早停"**

```text
每步 r_t = −ΔHPWL_t/D（ΔHPWL ≥ 0 ⇒ 每步都是负值）
一局累加 = −(ΔHPWL_1 + … + ΔHPWL_T)/D = −HPWL_final / D      ← 恰好抵消
⇒ 提前终止（死锁）会省掉后面所有负值 ⇒ 回报反而更高
实测一局量级（20 板完整专家布局）：|HPWL_final/D| min 1.21 ｜ 中位 7.95 ｜ max 22.04
```

**死锁罚分候选**（四选一 / 可组合）

| 方案 | 做法 | 评价 |
|---|---|---|
| (A) 只记录完成度、不罚 | — | ❌ 会诱导早停（数据如上） |
| (B) 固定终局罚分 `P = −C` | C ≥ 25（覆盖实测最大 22.04） | 严格但引入大稀疏负值；更稳的是**板自适应** `P = −λ·(HPWL_src/D)`，λ=3~5 |
| **(C′) 每放置一件给进度奖** | `r_t += λ_b·c_comp/D`，`c_comp` = 该件的**实测边际贡献**（`HPWL(全) − HPWL(去掉它)`），λ_b ≈ 1.5 | 因顺序固定 ⇒ 等价于"**按元件贡献加权的完成度进度奖励**"；量级自然、无巨值；需一张离线 `c_comp` 表 |
| (D) 死锁 episode 丢弃 | — | 无诱导，但**学不到"避免死锁"**、浪费样本 |

**单件边际贡献实测**（probe131，857 件）：`c/D` 中位 **0.026** ｜ p95 1.16 ｜ p99 5.94 ｜ **max 20.12** ⇒ **极度偏斜**：多数件几乎不产生 HPWL，少数巨件独占整局量级。（这条也解释了"93% 专家步非贪心"与"23.6% 迷茫步"：**大部分放置对 HPWL 几乎无差别**。）

**γ 的建议**：取 **γ = 1**。理由：目标是"最小化最终 HPWL"、episode 有限且会终止，本不需要折扣；而 γ<1 会让"冷 pad 的延迟代价"（首→次步距 3.85 步）被**二次打折**（`0.99^30 ≈ 0.74`）⇒ 系统性低估"为未来预留空间"的行为。

**现状**：**reward 未定义**（Owner："具体的 reward 后续再看"）；上述内容为**候选与定标依据**，等 reward 定案时直接取用。
