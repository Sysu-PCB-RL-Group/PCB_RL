## 三、关键发现

### 3.1 R1-R3（均匀放大 2×-4×）：全部成功，缩放定律清晰

```
倍数 ↑ → 收敛 episode ↑（2264 → 4335 → 6983）
倍数 ↑ → 前期 placed 更低（4.7 → 3.2 → 2.0），但后期追回来
倍数 ↑ → 最终 placed 反而更高（5.1 → 5.3 → 5.5）
```

小倍数时网络很快找到可行解；大倍数时前期探索更困难，但网络容量更大（head 维度增加），最终表现反而更好。**4 倍是最优设置**：最终 placed=5.5，且 R 提升幅度最大。

### 3.2 R4（20×）：一个反常现象

虽然 R 趋势是 ↑、best_R=200，但：
- 最终 placed 仅有 4.0（R1-R3 都在 5.1+）
- 后 20% 平均 R 比 R1-R3 更负（-903.0 vs -499.8~-729.8）

**解释**：120 维的 head_comp（96.7% padding）给 slot encoder 更多参数去学习 per-slot 特征。较大网络带来了意外的好处——head_comp 有 16×120 参数 vs 16×24（R3），容量更大。但 R 平均仍在变差，说明网络偶尔能找到好布局但不稳定。

### 3.3 R5（35×）：均匀放大的崩塌点

- best_R=200 但最佳在 ep 6217，此后 R 和 placed 都在下降
- 后 20% 平均 R = -1084.3（比前 20% 更差）
- 最终 5 轮全部 -1100（全被罚分）

**这是均匀放大的极限**。35 倍时 padding slot 占比 97.1%，即使 slot encoder 共享权重、mask 屏蔽 padding，网络也需要从 210 个 slot 中筛选 6 个有效元件。前中期偶尔能找到解（ep 6217 达到 200），但无法稳定——探索阶段的大部分时间都在混乱中浪费。

### 3.4 R6（不对称放大 200/3×）：彻底失败

- best_R 仅 150（从未达到满分）
- R 和 placed 都在持续下降
- 最终 5 轮全部 -1100

**双维度不对称是致命的**：元件维度 33× 但网格只有 3×，head_comp 有 200 维（大量 padding）但 head_x1/head_y1 只有 21 维（接近真实网格）。网络信号极度不平衡——选元件的 Q 值被 194 个空 slot 的噪声淹没，而坐标选择几乎没有容错空间。

## 四、综合结论

### 4.1 缩放曲线（最重要的图）

```
放大倍数   2×──3×──4×────────20×────────35×
收敛性    ✅  ✅  ✅        ⚠️         ❌
placed     5.1 5.3 5.5      4.0        3.0
稳定性    稳  稳  稳        勉强        崩溃
```

### 4.2 固定维度方案可行性

| 条件 | 结论 |
|---|---|
| 均匀放大 2×~4× | ✅ **完全可行**，训练稳定收敛 |
| 均匀放大 4×~20× | ⚠️ 勉强可行，能收敛但不稳定，placed 质量下降 |
| 均匀放大 > 20× | ❌ 不可行，模型崩溃 |
| 不对称放大（一个维度极大、另一个正常） | ❌ **致命**，比均匀极大放大更差 |

### 4.3 推荐实践

1. **生产环境优先选择 3×~4× 均匀放大**
2. MAX_MOVABLE 和 GRID_W/H 必须同步缩放，不能一个很小一个很大
3. 如果目标数据集 N_movable 均值=200，则 MAX_MOVABLE=600~800（3~4×），太大会适得其反
4. 小板的测试结论可直接推广：**固定维度是可行的，关键在选对放大倍数**

### 4.4 异常现象记录

| 现象 | 出现测试 | 判断 |
|---|---|---|
| Best_R=200 但 placed 很低 | R4（20×） | 网络偶尔找到完美放置但无法复现，整体质量差 |
| Best_R=200 但 R 趋势下降 | R5（35×） | 后期已无法复现早期的最好结果，收敛不稳定 |
| R 趋势上升但 placed 很低 | 无 | 所有测试中 R 和 placed 趋势一致 |
| Padding 噪声淹没有效信号 | R5, R6 | 97% 以上 padding 比例时发生 |
