## 1. KiCad bbox 坐标修复（根因级 bug）

**文件**：`utils/kicad_utils/kicad_utils.py`

### 问题
原代码把 KiCad 元件的包围盒 AABB 记为 `(x1=left, y1=bottom, x2=right, y2=top)`，即把 `GetBottom()`（y 大值）放在 y1、`GetTop()`（y 小值）放在 y2。由于 pcbnew 坐标系 **Y 轴向下**，`GetBottom()` 得到的其实是**视觉底部（y 值大）**，`GetTop()` 是**视觉顶部（y 值小）**，所以原实现把 y1/y2 颠倒了，**不是标准 AABB（y1 < y2）**。

### 后果
- `out_of_bounds_area` 用了 `max(0, bymax - bymin)` → 因 y1 > y2 恒为 0，**出界检测完全失效**；
- `bbox_overlap_penalty` 的 dy 计算错乱 → **重叠 / 间距检测全部失效**。

这意味着早期训练里"元件是否出界、是否重叠"这一最基础的约束判断是坏的。

### 修复
改为 `(x1=left, y1=top, x2=right, y2=bottom)`，保证 y1 < y2，恢复出界与重叠检测的正确性。

### 冲突情况
该文件**未与远程冲突**，自动合并成功。

## 2. 专家轨迹 reward 去惩罚（BC/TD 学习的根因修复）

**文件**：`env/expert_trajectory.py`

### 问题
原专家轨迹的 reward 计算同时包含"惩罚项（重叠/软间距/出界）"和"品质奖励"。若专家示范的 reward 为负，会导致：

- **Phase 1 BC 预训练**：教 agent"照着专家做，回报却是负的"，学到错误的行为模式；
- **Phase 2 常驻专家 buffer**：持续向 Q 值注入负信号，把正确行为"带偏"。

这是此前 **Button / Connector 两块板学不会** 的根因之一。

### 修复
在 `_compute_expert_reward` 中调用环境奖励时传入 **`apply_penalties=False`**（去掉惩罚项），使专家示范 transition 的 reward 恒为"零惩罚的正向品质分"（品质 + 完成）。同时新增 `placement_step` 参数，使每个子步骤的奖励分配更精确。

### 关键说明
- 这**不会**让 RL 阶段失去惩罚约束——真实环境 `env.step()` 依然按 `apply_penalties=True` 施加出界/重叠惩罚，agent 在 RL 阶段仍会被正确约束；
- 只影响**专家示范数据**，让"示范 = 正确行为"这个语义成立。

### 冲突情况
与远程**内容冲突**（远程版用 `apply_penalties` 默认值即含惩罚，回归了该 bug）。**本方案保留你的去惩罚版本**，详见文末[冲突决策](#合并冲突决策记录)。

## 3. 约束检测区分层（双面 PCB 修复）

**文件**：`env/pcb_layout_env.py`

### 问题
原碰撞检测把"不同层（顶层/底层）的元件"也判为重叠/间距违规。对**双面 PCB**而言，顶层和底层的元件物理上不会碰撞，但会被误判，导致错误惩罚。

### 修复
在 `_check_constraints` 中增加层判断：`if other.layer != component.layer: continue`（不同层的元件跳过重叠/间距检测），只有同层元件才判约束。

### 兼容处理
远程版将同一函数命名为 `_detect_collisions` 且无层区分。合并时保留你的 `_check_constraints`（含层区分），并**添加一行别名** `_detect_collisions = _check_constraints`，使任何按远程名字调用的代码也能正确工作。

## 4. Reward Clip（方案 B，稳定 TD 目标）

**文件**：`env/pcb_layout_env.py`、`config/argument.txt`

### 内容
在 `_calculate_reward` 最后对单步 reward 做截断：

```python
reward = float(np.clip(reward, Config.REWARD_CLIP_MIN, Config.REWARD_CLIP_MAX))
```

新增配置（`config/argument.txt`）：

```
REWARD_CLIP_MIN = -30.0   # 单步 reward 下限
REWARD_CLIP_MAX =  60.0   # 单步 reward 上限
```

### 目的
- 防止单步出现**极端惩罚值**（如巨额重叠惩罚）主导 TD 目标，造成值函数发散；
- 保留完成 / 品质奖励的比例信息，使学习信号更稳定。

### 附带影响（测试层面）
早停测试 `test_early_stop_on_low_reward` 因此需要**多次违规**累计 reward 跌破阈值才触发早停，测试已相应更新（见[测试更新](#8-测试更新)）。

## 5. Double DQN + 掩码兜底

**文件**：`dqn/agent.py`

### 改动一：Double DQN
原为标准 DQN（`target = r + γ · max Q_target(s', a')`），存在**过估计**问题。改为 Double DQN：

- **在线网络** `q_net` 选择下一状态最优动作：`best_actions = argmax_a Q_online(s', a)`；
- **目标网络** `target_net` 对所选动作求值：`Q_target(s', best_actions)`。

这样解耦了"选择"与"求值"，缓解过估计，使 TD 目标更稳定。

### 改动二：掩码兜底（`_apply_next_state_mask`）
把原来分散在目标计算里的掩码逻辑抽成独立方法 `_apply_next_state_mask`，供 online/target 网络**共用**：

- `nsid=0`：用 placed_flag 屏蔽已放置元件；
- `nsid=1`：用 grid_width 屏蔽越界 x1；
- `nsid=2`：用 grid_height 屏蔽越界 y1。

并新增**兜底**：若某样本的候选动作被全部屏蔽（如已无未放置元件），将整行重置为 0，避免 `argmax` 选中 `-inf` 产生 NaN loss。

## 6. 变异后校验回退（专家数据纯净性）

**文件**：`env/expert_trajectory.py`

### 内容
在 `_mutate_component_state`（专家轨迹多样性变异）之后，执行与 `env.step()` **完全相同的约束检测**（硬重叠 + 软间距 + 出界 + 禁止区域）：

- 一旦变异导致**任何违规**，立即回退到变异前的原始干净状态；
- 保证专家示范 transition 的 reward 恒为"零惩罚的正向品质分"。

### 目的
专家源布局是干净的，变异只是用于增加轨迹多样性的"探索"。若变异引入违规示范，会污染 Phase 2 的 TD 学习。此改动确保**示范数据纯净**。

## 合并冲突决策记录

### 背景与流程

本地工作区有**未提交的核心改动**（bbox 修复、专家 reward 去惩罚、层区分、Reward Clip、Double DQN 等），远程 `main` 新增了提交 `c8d4f29`（专家轨迹 A/B 对照实验）。为安全整合，采用 **`git stash push -u` → `git pull` → `git stash pop`** 三步流程：

1. **存档**：先 `git diff > ..\my_core_changes.patch`（把核心改动存成补丁备份到仓库外）；
2. **暂存**：`git stash push -u`（暂存所有改动含未跟踪文件，工作区变干净）；
3. **拉取**：`git pull origin main`（Fast-forward，无冲突）；
4. **恢复**：`git stash pop`（放回改动，触发 4 个文件冲突）。

### 问题 1：命名冲突 —— 同一功能两个函数名

**现象**：远程与本地对"碰撞/约束检测函数"取了不同名字，且依赖该函数名的调用点分散在 `expert_trajectory.py` 和 `pcb_layout_env.py` 两个文件中。

| | 远程版（upstream） | 本地版（stashed） |
|---|---|---|
| 函数名 | `_detect_collisions` | `_check_constraints` |
| 层区分 | ❌ 无 | ✅ 有（`if other.layer != component.layer: continue`）|
| apply_penalties 参数 | ❌ 无 | ✅ 有 |

**为什么保留本地版**：本地版是**远程版的功能超集 + 两个已验证的根因修复**（层区分修复双面 PCB 误判、apply_penalties 修复专家 reward 含负惩罚的 bug）。远程版功能是本地版的子集。

**解决方案**：在 `pcb_layout_env.py` 中保留本地版 `_check_constraints`（含全部逻辑），并**追加一行别名** `_detect_collisions = _check_constraints`。这样：
- 远程代码（若调用 `_detect_collisions`）→ 走别名，仍含层区分 + 惩罚控制，正确；
- 本地代码（调用 `_check_constraints`）→ 走原函数，正确；
- 两版调用点**都不会报错**。

### 问题 2：专家 reward 计算逻辑分歧

**现象**：同一处 `_compute_expert_reward`，远程与本地实现不同：

- **远程版**：专家 reward **含惩罚项**（调用 `apply_penalties` 默认值 True），意图是与训练 reward "同步"；
- **本地版**：专家 reward **去惩罚项**（`apply_penalties=False`），因为"专家示范 = 正确行为，不该带惩罚"。

**为什么保留本地版**：
- 本地版修复的是**已实测验证的根因 bug**——此前 Button/Connector 板学不会，就是因为专家 reward 含负惩罚：Phase 1 BC 教会"照着专家做回报为负"，Phase 2 常驻 buffer 持续注入负信号；
- 远程版相当于**回退了该修复**（重新引入惩罚项）。

**解决方案**：整体采用本地版 `_compute_expert_reward`（含 `apply_penalties=False` 参数 + `placement_step` + `_has_new_hard_violations` 变异回退）。**但此点与远程 A/B 对照实验的设计意图可能冲突，需与组员沟通对齐**（详见"与远程 A/B 对照实验的关系"）。

### 问题 3：JSON 专家数据内容冲突 + 删除冲突

**现象**：
- `开关小板_expert.json`：两边都改过 → **内容冲突**；
- `灯板2_expert.json`：远程删除、本地改过 → **删除冲突（DU）**。

**解决方案与理由**：
- **开关小板 JSON → 采用本地版**（`:3:` / theirs）：本地版是用修复后代码重新生成的、**reward 全正**的数据，与本地 `apply_penalties=False` 的代码逻辑保持一致；
- **灯板2 JSON → 尊重远程删除**：远程主动删除，且专家数据会在训练时按需重新生成，删除不影响功能。

### 问题 4：PowerShell 重定向导致文件编码损坏

**现象**：在 PowerShell 中用 `>` 重定向执行 `git show :3:env/pcb_layout_env.py > file` 提取文件，会把文件写成 **UTF-16 LE（带 BOM）** 编码。Python 无法加载 `.py` 文件，报 `source code string cannot contain null bytes`。

**为什么发生**：Windows PowerShell 的 `>` 重定向默认使用系统 Unicode（UTF-16）编码写文件，与 Python/UTF-8 不兼容。

**解决方案**：编写 `_fix_encoding.py`，读取 UTF-16 BOM（`FF FE` / `FE FF`）→ `decode("utf-16")` → 以 UTF-8 重新写回。修复了 `pcb_layout_env.py`、`expert_trajectory.py`。

**教训**：在 Windows PowerShell 中**不要用 `>` 重定向 `git show` / `git cat-file` 的输出到文件**；应改用 `git checkout`、或用 Python 的 `subprocess` 写文件。
